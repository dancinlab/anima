## 판정 ② — 🔧 새 계기 결함: **r2 의 순열 영가설이 붕괴한다** (3 중 2)
`sst2_free`·`ko_free` 에서 `sd_null = 0.00000` ⟹ **MDE 가 0** 으로 찍힌다. 이건 "무한 검정력"이 아니라 **영가설이 죽은 것**이고,
`power-before-negative-verdict`(음성 판정 전 검정력 먼저) 위반이라 그 두 칸은 **검정력 있는 음성으로 인용 불가**다.
특히 `ko_free` 는 씨앗 9304·9305·9306 이 **소수점까지 동일한 +0.00000** 이고 δ 도 0 — 저장소가 이미 이름 붙인 신호
(`flat-across-manipulations-means-the-lane-is-dead` · `repeated-identical-output-must-not-multiply-evidence`)에 정확히 해당한다.
⟹ **"0 으로 측정됐다"가 아니라 "그 코퍼스에서 r2 기계가 상수 0 을 뱉는다"**. 기전 추정(미확정): 진리가 가법인 영가설 세계에서
r2 의 적합이 δ=0 을 **정확히** 골라 이득이 항상 0 이 되고, 그래서 분산이 사라진다. amazon(셀 100,626)에서는 살아있다.

⟹ **r2 는 음성 판정용 렌즈로 그대로 쓸 수 없다.** 양성 방향(REOPEN 여부)에는 유효하나, 음성을 굳히려면 영가설 붕괴를 먼저 고쳐야 한다.

## 판정 ③ — 스코프 확장은 **검정력이 살아있는 칸에서만**
사전등록 branch 2("셋 다 |EARNED|≤0.02 → 게이팅형→순서형 확장")는 **amazon 30k 에서만 온전히 충족**된다(영가설 정상·MDE 0.00163).

> 자연 코퍼스에 전이 가능한 재조합 연산자가 없다는 판정은 **게이팅 형태(r0)에서 검정력 있게** 성립하고,

## 왜 이 검사인가 — 캠페인 전체를 겨눈다
`earned` 캠페인의 모든 판정(H_9944 · H_9946 · H_9949 · H_9951 · H_9952 · H_9953 · H_9968)은
`anima-py evaluate --earned` 를 **`--kernel` 기본값 하나로만** 돌려서 나왔다. 그런데 코드를 읽으면
추정기는 **상호작용의 함수 형태를 3 종** 갖고 있다(`cli/earned.py::fit_and_score`):

| 커널 | 모형 | 뜻 |
|---|---|---|
| **r0**(기본 · 내가 쓴 것) | `z = α_A + γ_B + δ·(B·α_A)` | 게이팅/부호뒤집기 — XOR 부류(부정·역접·반어) |
| r1 | `z = α_A + γ_B + δ·φ(α_A+γ_B)` | 문턱/순서 — **코드에 이미 MEASURED BLIND** (순서 양성통제 +0.067 vs bar +0.30) |
| **r2** | `z = α_A + γ_B + δ·tanh(u_A − v_B)` | 일반 순서 — 차이가 표현 가능, `|A|+|B|` 자유도 매입 |

⟹ 내 `DATA-ADDITIVE` 는 엄밀히 **"r0 형태의 전이 가능한 연산자가 없다"** 였지 **"연산자가 없다"** 가 아니다.
이건 이 저장소가 이미 이름 붙인 함정의 실사례다 — `default-path-census-frame-blindspot`
(기본경로만 세면 거짓 보편명제가 허가되고, **opt-in 플래그가 사각지대**).

## 계기 — 새 코드 0 · 조작은 기존 플래그 하나
`anima-py evaluate --earned <tsv> --kernel r2` (+ 나머지 플래그는 **각 코퍼스의 r0 원런과 동일**하게 고정
= `--kernel` 만 움직이는 짝지은 대조). 인증은 계기가 **스스로** 한다:
- **커널맞춤 양성통제**: `alive_mode = "order" if kernel in ("r1","r2") else "xor"` — 코드 주석 그대로
  *"순서 커널을 XOR 진리로 인증하는 건 순서에 대해 아무것도 증명하지 못한다"*.
- **G-DOF**(r2 전용): 늘어난 자유도가 held-out 이득을 **환각하지 않는지** — 가법-진리 세계에서 `|EARNED| ≤ δ_eq`.
- 하나라도 실패 → `verdict = INVALID`, **본 바는 읽지 않는다**.

측정 전 확인된 사실(발사 로그): **G-ALIVE synthetic ORDER = +0.68701 (bar +0.30) PASS** —
r2 는 r1 이 눈멀었던 순서형 연산자를 **실제로 본다**. 즉 이건 죽은 팔이 아니라 살아있는 다른 렌즈다.

## 동결 판정표 (숫자 읽기 전)
1. **G-ALIVE(ORDER) 또는 G-DOF 실패** → `INVALID` — 커널 미인증. 본 바 안 읽음. r1 전례(+0.067)가 이게
   형식적 위험이 아님을 보여준다.
2. **인증 통과 ∧ 세 코퍼스 모두 `|EARNED_r2| ≤ 0.02`** → 🟢 **캠페인 결론 확장(강화)**: "자연 코퍼스에
   전이 가능한 재조합 연산자가 없다"가 **게이팅 형태를 넘어 순서 형태까지** 성립. 기존 카드들의 스코프 문구를
   "r0 한정"이 아니라 "두 형태에서"로 갱신.
3. **인증 통과 ∧ 어느 코퍼스든 `EARNED_r2 − EARNED_r0 > 0.02`** → 🔴 **REOPEN**: 그 코퍼스엔 **순서형**
   전이 정보가 실재하고, 내 `DATA-ADDITIVE` 판정 전부는 **r0 한정**으로 강등된다. 특히 H_9968
   (데이터-스케일 CLOSED)의 스코프가 좁아진다.
4. **G-DOF 는 통과인데 r2 가 r1 을 δ_eq 이상 못 이김** → 코드 규칙대로 r1 으로 강등(추가 자유도가 값을 못 함).

## 정직 경계
- r2 는 `|A|+|B|` 자유도를 사므로 **양의 판독을 곧바로 연산자로 읽으면 안 된다** — G-DOF 가 그래서 필수 게이트고,
  통과했더라도 상승분은 r0 대비 δ_eq(0.02) 초과분만 실질로 센다.
- 커널 3종이 **함수 형태 전체를 망라하지 않는다**. 셋 다 0 이어도 주장은 "이 세 형태에서"까지다

- DIRECTIONAL 스크리너(p9 · regime=natural). cement 는 engine-native `anima-py` 판독으로만.
