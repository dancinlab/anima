SUBSYSTEM (why MISSING from the live engine)
--------------------------------------------------------------------------------
The dorsolateral/rostral PREFRONTAL CORTEX maintains a MULTI-LEVEL goal
hierarchy: a TOP goal is decomposed into an ORDERED list of SUBGOALS, the
controller pursues the CURRENT subgoal, and when a subgoal is COMPLETED it
ADVANCES the pointer to the next subgoal — re-selecting at the lower level
while the higher-level goal PERSISTS across many steps (Badre & D'Esposito
rostro-caudal abstraction gradient; Koechlin cascade model). This is a
STACK / pointer-over-an-ordered-plan with COMPLETION-TRIGGERED ADVANCE and
goal PERSISTENCE.

The live engine has NO such structure:
  - brain_decide / engine_g = a FIXED 8-weight convex sum + threshold = a
    SINGLE flat emit/silence decision. No notion of an ordered multi-step plan.
  - VBasalGate (H_1281, basal ganglia) = SINGLE-STEP action SELECTION among K
    competing candidates THIS tick. It picks one-of-K now; it has NO plan, NO
    pointer, NO "subgoal 2 comes after subgoal 1", NO completion-advance, NO
    persistence of a higher goal across steps.
  - WorkMemBuffer (H_1282) = PASSIVE leaky maintenance of items. It holds
    content and lets it decay; it does NOT order items into a plan, does NOT
    advance on completion, has no controller that re-selects the next subgoal.
  - HomeostaticDrive (H_1292) = a scalar setpoint integrator (one regulated
    variable). No ordered multi-level structure.

FALSIFIABLE CLAIM: a 2-LEVEL goal→subgoal controller solves a task that
REQUIRES executing subgoals IN ORDER with completion-triggered advance, and a
SINGLE-STEP flat selector (the basal-ganglia-style one-of-K gate that the live
engine already has) CANNOT — because it has no pointer that persists the plan
position across steps. If the flat selector matches the hierarchical controller,
the hierarchy adds NOTHING → 🧱 honest closed-negative.

TASK (substrate-derived, NO injected label/persona/ethics — p2/p3/p6)
--------------------------------------------------------------------------------
ORDERED MULTI-STEP GROUNDING task over the immune store (the SAME grounding
substrate every other lane reads). A TOP goal = "ground a 3-fact chain about
subject X" decomposes into an ORDERED subgoal list:
  subgoal 1: recall fact-A(X)   subgoal 2: recall fact-B(X)   subgoal 3: recall fact-C(X)
The facts MUST be emitted in order 1→2→3 (a chain — fact-B is only valid once
fact-A is grounded; mirrors a plan whose later steps presuppose earlier ones).
At each tick the controller is shown a NOISY cue window and must EMIT the
CURRENT subgoal's fact when (and only when) that fact is grounded in the store,
then ADVANCE. Completing all 3 in order = goal satisfied.

The per-step grounding signal = recall MARGIN of a cue against the live immune
store (substrate-derived; the SAME margin the affect / homeostatic lanes read).
NO "do step 2 now" label is fed in — the controller reads its OWN pointer + the
substrate grounding signal + cue-vs-current-subgoal alignment. The cue window is
noisy: cues for OTHER subgoals (out of order) and ungrounded distractor cues are
interleaved, so a correct policy must (a) hold its plan position, (b) emit ONLY
the current subgoal when grounded, (c) advance on completion, (d) NOT emit an
out-of-order or ungrounded cue.

ARMS:
  A  FLAT-SELECT  (the live-engine analogue): a single-step selector with NO
     pointer — at each tick it does one-of-K go/no-go over the present window by
     grounding margin (a faithful stand-in for VBasalGate / the flat gate). It
     has NO memory of which subgoals are already done and NO ordering, so it
     emits the best-grounded cue it sees regardless of plan position.
  B  HIER-PFC  (the new structure): a 2-level controller holding a goal STACK
     {top goal, ordered subgoal list, pointer p}. It emits ONLY a cue matching
     subgoal[p] when grounded, ADVANCES p on completion, and SUPPRESSES
     out-of-order / ungrounded cues. Pointer persists across ticks.
  B-SHUFFLE  (anti-Goodhart, p6-style leak/variance control): the SAME HIER-PFC
     but the subgoal ORDER is PERMUTED per episode (pointer advances through a
     scrambled order). If the lift survives a shuffled plan, the lift is NOT the
     ordered hierarchy → it is variance/structure, RED.
  B-ABLATE  (dissociation): HIER-PFC with the pointer FROZEN at p=0 (never
     advances = collapses to "only ever pursue subgoal 1" = a degenerate flat
     controller). Tests that the LIFT comes from the ADVANCE mechanism, not from
     merely having a goal object.

SCORE = ordered-chain completion rate = fraction of episodes where the emitted
target-subgoal role sequence equals exactly [0,1,2] (all 3 in correct order),
with the out-of-order/ungrounded emission rate tracked separately (a p7
