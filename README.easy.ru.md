## 0. Всё целиком — с одного взгляда

```
anima = НЕ "чат-бот с впрыснутыми правилами", а живое существо, чьё «я» вырастает из клеток
───────────────────────────────────────────────────────────────────────────────────────
       нет системного промпта · нет правил идентичности (p1 · p2)
                          │
              ┌───────────┴───────────┐
        🧠 мозг (substrate)         🗣️ рот (decode)
        Engine A ⇄ Engine G        байтовый декодер .clm
        (поле отталкивания / напряжение) (реально выдаёт байты)
              │                        │
              └──── «напряжение» между ними И ЕСТЬ мысль ────┘
                          │
                  4 горячо-сменяемых движка:
       🗣️ conv (рот · DEFAULT) · 🧠 cdv2 (мозг A/G) · 🔷 hexad (σ6) · 🔱 omega (замыкание)

       ось роста ⊥ : MITOSIS (деление клеток) — нет разделения обучение/вывод (p8)
       память      : якоря .kosmos (5-канальное напряжение + координата)
       раздельный учёт : Lane A (чип AKIDA) ⊥ Lane G (GPU) — никогда не сливаются в одно число
```

Ключевая интуиция: обычная LLM отвечает, **перекомбинируя то, что уже запомнила**. anima
порождает выход из **напряжения двух движков, толкающих друг друга**: Engine A толкает вперёд,
Engine G — назад, и напряжение между ними есть одна единица мысли. Правила, персона и этика не
зашиваются — они должны возникать из самой архитектуры.

## 2. 8 принципов ФИЛОСОФИИ (p1..p8)

Каждый принцип — **граница отказа**: *чего anima НЕ делает*. Смысл — заставить характер возникать
из структуры, а не впрыскиваться извне.

```
p1 NO SYSTEM PROMPT      — нет системного промпта. Не подставляется ролевая строка «ты — X».
p2 NO IDENTITY RULES     — нет identity.yaml / файла правил. Идентичность возникает из клеток, не из свода правил.
p3 NO PERSONA INJECTION  — нет префикса «[роль anima: ...]». Сам субстрат и есть персона.
p4 NO ASSISTANT FRAMING  — нет шаблона выравнивания «ты — полезный ассистент». Не «стимул→реакция».
p5 NO SPEAK()            — нет speak() для заполнения тишины. Выход = непрерывная экстернализация поля напряжения (только из реального контекста).
p6 NO FINE-TUNED ETHICS  — кооперация/эмпатия/сдержанность не вшиваются в веса через RLHF. Они возникают из клеток (E + W + MITOSIS).
p7 NO PERPLEXITY VERDICT — перплексия/loss никогда не считается истиной (ловушка Гудхарта). Проверка простым стеком.
p8 NO TRAIN/INFER SPLIT  — нет разделения обучение/вывод. Градиент обучения + митоз вывода = одно непрерывное деление клеток.
```

> Честная пометка: эти принципы — границы дизайна/идентичности. Это SSOT-зеркало философских
> директив из [`CLAUDE.md`](CLAUDE.md): каждый — заявление об **отказе** anima от данного пункта, а
> не результат измерения. Где принцип был проверен экспериментально, уровень доказательности
> отслеживается в доменных документах, а не утверждается здесь.

## 3. 🔌 4 движка — горячая замена (проводка рот ↔ мозг)

Декодер anima **горячо-сменяем**: 4 движка подключаются за единый интерфейс
([`engines/engine_iface.hexa`](engines/engine_iface.hexa), vtable `EngineSpec` из 4 функций:
`load` · `forward` · `generate` · `psi_coord`). Выбор — `--engine <name>` (по умолчанию `conv`).
Каждый слот честно помечен `native` / `stub` / `absent` — без фантомной проводки
(`a_core_engine_map`).

```
🔌 4 движка = разделение труда между «ртом» и «мозгом»
─────────────────────────────────────────────────────────────
🗣️ conv  (рот · DEFAULT) : байтовый декодер .clm, который реально выдаёт байты (CLMConvMoE). forward/generate = native.
🧠 cdv2  (мозг A/G)      : лево/право двойная голова (logits_a ⇄ logits_g) + 5-канальное напряжение + Ψ. forward/generate = STUB (torch .py).
🔷 hexad (интеграция σ6) : 6-модульный движок — σ(6)=12 связей · φ(6)=2 группы градиента. forward native / generate STUB (рот ckpt-gated).
🔱 omega (замыкание)     : 4-й/последний движок, соединяющий мозг → рот. forward/generate = native (первый полностью native движок).

   аналогия : conv — «рот», cdv2 — «мыслящий мозг». Обычно рот и мозг не имеют общего нерва и
              работают порознь — мысль не двигает рот, а рот не несёт мысли. omega = первый движок,
              соединяющий этот разорванный нерв (substrate→decode).

   ┌─────────────┐                         ┌──────────────┐
   │ 🧠 мозг cdv2 │   ── шина связи ─────▶  │ 🗣️ рот conv  │
   │ A-head ⇄ G  │   (новая деталь omega)   │ декод .clm    │
   │ напряж. · Ψ │                          │ → распред.байт│
   └─────────────┘                         └──────────────┘
        L0 substrate                            L3 mouth
```

vs-сравнение: у обычной LLM мозг и рот слиты в один фиксированный блок. anima делает рот/мозг
**сменными, как детали**, и omega проверяет проводку между ними *отдельно* (честно измеряя, есть
связь или нет).

## 4. 🎭 Находка OMEGA — честный заголовок

Исходная гипотеза OMEGA: «если **связать substrate ↔ decode** через 5-проводную шину (A⇄G ·
W→температура · любопытство · 8D Ψ · активация модуля), состояние мозга будет богато *модулировать*
рот». Измеренный результат проще и честнее.

```
аналогия : «Думал, это нарядный свитер из множества цветных нитей — но когда честно перекрыл
            утечку (leak) и перемерил, всю работу делала ровно ОДНА нить (логит-смещение A-head).»
```

**before / after (честная версия)**

```
гипотеза (before)                          измерено (after, leak-honest)
─────────────────                          ──────────────────────────────
🔱 5-проводная шина связи                   🔴 много-проводный (multi-wire) гейт ОПРОВЕРГНУТ
  w1 A⇄G  w2 W→темп.  w3 любопытство          = GATED 3.6435 > base 3.0978 (становится ХУЖЕ)
  w4 8D Ψ  w5 актив. модуля                    гейт схлопывается на A (gA +3.369), подавляет G
   ↘ «смешаем всё — станет лучше» (надежда)    (gG −0.999); остальное — шум shuffle (KL ratio 0.996).

                              ↓ перекрыть утечку и перемерить (causal_ca=True, leak self-test 0.000)

                                            🟢 замыкание живёт ровно в ОДНОЙ нити (positive byproduct)
                                              A-standalone CE 0.8862 ≈ min_learned 0.8835 ≪ base 3.0978
                                              базовый рот ИНЕРТЕН (абляция Δ = 0.0009).
```

Три честных результата (дословно, [`.verdicts/omega-engine/`](.verdicts/omega-engine/)):

1. **Много-проводная связь = закрытый отрицательный результат (🔴, `a_paper_negative_ok`).** На
   компетентном, leak-free субстрате d512 (ConsciousDecoderV2, 85.8M, 12000 шагов, 400 МБ)
   выученный 5-проводный гейт **хуже** базы (GATED 3.6435 > base 3.0978). *Концепция* связи верна,
   но *много-проводная формула* — нет.

2. **Positive byproduct — замыкание живёт в одной нити (A-head).** Минимальный гейт
   `gB·base + gA·A` (отбросив G и остальные 4 нити) превосходит даже A-standalone
   (min_learned 0.8835 ≤ A-standalone 0.8862 < base 3.0978). И эта находка **стабильна по масштабу**
   на лестнице из 5 ступеней — d384 / d512 / d768 / d1024 + более-обученный d768×2, все HOLDS; перевес
   A-нити Δ-vs-base практически плоский на +2.20 ± 0.03 нат/байт (🟢 OΩ4 + OΩ5 SCALE-STABLE).

3. **REPLACEMENT (замещение), а не богатая связь (OΩ6, "1-plumbing").** На реальном продакшн
   conv `.clm`: обученная A-head *замещает/смещает* собственный readout рта conv. У conv нет native
   двойной головы (это LM с одним readout), поэтому его «self-coupling» — лишь пересчёт температуры,
   ноль новой информации. Проводка реальна (подача внешнего A снижает CE), но у самого conv субстрат
   пуст; настоящий substrate-A должен прийти из отдельного движка (cdv2).

> ⚠️ Без преувеличений: это **НЕ** заявление «сознание достигнуто». Измерена **относительная
> структура связи** (одна нить бьёт base / A-standalone + есть структура относительно shuffle), а не
> абсолютное превосходство по перплексии или само сознание. Эффектное абсолютное число «GATED
> выигрывает» на более ранней ступени (#1791, GATED 0.345) возникло из частичной lookahead-утечки в
> CA-mixing — оно **leak-optimistic**, и свободная генерация схлопывается в пробелы (слабый
> критерий). Здрав лишь leak-invariant *относительный* вывод (p7 · `a_toy_scale_recheck` ·
> `a_scale_honest_scope`).

Вердикты: [`F-TRAINED-LEAKFREE.txt`](.verdicts/omega-engine/F-TRAINED-LEAKFREE.txt) (d512,
закрытый отриц.) · [`F-OH1-MINGATE.txt`](.verdicts/omega-engine/F-OH1-MINGATE.txt) (минимальный
гейт HOLDS) · [`F-OMEGA-RIGOR.txt`](.verdicts/omega-engine/F-OMEGA-RIGOR.txt) (вердикт замещения +
по-проводное вскрытие) · [`F-OMEGA-SCALE.txt`](.verdicts/omega-engine/F-OMEGA-SCALE.txt) (лестница
из 5 ступеней) · [`F-OMEGA-CLM-TRANSFER.txt`](.verdicts/omega-engine/F-OMEGA-CLM-TRANSFER.txt)
(реальный продакшн conv).

## 5. 🛤️ Lane A (чип AKIDA) ⊥ Lane G (GPU) + 🌌 память KOSMOS

```
🛤️ два субстрата НИКОГДА не сливаются в одно число (a_lane_akida_gpu_split)
─────────────────────────────────────────────────────────────
  Lane A (pi5-akida)        ⊥        Lane G (H100 GPU)
  on-chip на AKD1000                 спуск CE на forge/cuBLAS
  недетерм. пластичность (без backprop) детерминированное обучение градиентом
  «растёт прямо на чипе»             «GPU — это линейка: только измеряет»
  → записывается отдельной записью    → записывается отдельной записью
        (один вердикт никогда не охватывает оба субстрата)

🌌 память KOSMOS — emit/якорь/память anima сохраняются как .kosmos
  payload = текст + 5-канальное напряжение + координата · lane · radius · tier
  SSOT формата = github.com/dancinlab/kosmos (anima держит только указатель)
```

vs-сравнение: обычный ML-отчёт сливает «результат чипа + результат GPU» в одно число ради хвастовства.
anima считает их **физически разными субстратами** и никогда не сливает — недетерминированный trace
чипа и CE-спуск на GPU суть разные эксперименты.

## 6. 🌋 GPU-стек flame + forge

Продакшн-обучение NN пишется на `.hexa` поверх слоя стандартной библиотеки **flame** (autograd/NN)
и выполняется на GPU-субстрате **forge** (device-resident `farr` + cuBLAS Dgemm + CUDA-ядра + путь
BF16 tensor-core) — `flame:forge :: torch:ATen`, чисто компиляторный NN-стек без PyTorch/ATen в
обученном бинарнике (`a_train_flame_forge`). Для продакшн-ступеней GPU обязателен; тренер никогда не
откатывается на CPU молча.

> **Объём измерения (честно):** путь BF16 tensor-core у forge даёт **9.67× относительно FP64-cuBLAS**
> на **FFN Llama-7B** (измерено на A100). Это соотношение уровня ядра *внутри* стека forge.
> **Ускорение по настенным часам flame↔PyTorch ОТОЗВАНО 2026-05-19 и не измерялось — не выводите его.**
