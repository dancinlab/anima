## 1. 공격 A (실패) — "c2는 균일상수만 봐서 약한 null 아닌가"

수요가 expert별로 이질적이므로 진짜 open-loop null은 **per-expert 정적 상수**여야 한다고 보고 c4를 새로 만들어 붙였다 (레벨 스칼라는 c2·ORACLE과 **동일 grid·동일 PILOT 선택규칙**).

```
c4  (warmup 300 step 에서 1회 적합 후 영구 동결 · 온라인 피드백 0 · 인과적)
   fit 5.6523   Δ(c4 − c2) = −0.6397  t=−5.91   ← c2 보다 나쁘다
   Δ(EXP − c4) = +1.1832  SEM 0.0957  t=+12.37  p=1.6e-10  (20/20)

c4h (사후 full-run per-expert 상수 · grid 전수 hindsight = 정적 shape 의 상한)
   fit 6.6291   Δ(c4h − c2) = +0.3371  t=+6.24   ← 정적 shape 로 얻는 최대이득
   Δ(EXP − c4h) = +0.2063  SEM 0.0347  t=+5.94  p=1.0e-05  (18/20)  ← 온라인 추적의 순기여
```

⇒ **공격 실패.** EXP는 *사후* 정적 shape 상한마저 유의하게 이긴다. c2(=g 1.0)는 상수곡선의 실제 argmax이고(pilot curve peak, 정수 kink 포함 grid), c2h는 20 seed 전부에서 c2와 동일 → "grid 전수 최선"은 사실. **이득은 정적 FORM이 아니라 온라인 추적**이다. 본 주장 (1)은 강화된다.

## 2. 공격 B (성공 · 치명) — abl/abl_mm은 **setpoint를 제거하지 못한 가짜 ablation**이다

코드 두 줄:

```python
c   = np.full(E, MEAN_PE)   # = 2.0  ← 상수곡선의 argmax = c2 의 용량 그 자체 (= 최적 레벨)
zmu = np.full(E, 1.0)       # ← r* = ema/c = 1  ⟺  c == dem  ⟺  바로 그 θ=1.0 절대 setpoint
```

z-tonic은 `c ← c·exp(η·z)`, `z=(r−EMA r)/σ` — **로그공간 적분기이고 레벨 복원력이 0**이다. 레벨은 오직 **초기화**로만 앵커된다. 그런데 그 초기화가 정답(c=2.0=c2)이고, `zmu` 초기값 1.0은 문자 그대로 setpoint 비율이다. ⇒ **ablation 대상인 '절대 레벨'을 free parameter로 정답에 세팅해 준 것** = 그 양에 대한 검출력 0 (체크리스트 4항의 항진성을 *ablation arm*에 적용한 케이스).

### PROBE C — 레벨 앵커를 init에서 제거 (seed별 무작위 c0 · 운영대역 log-uniform)

```
                                   fit     cap    Δ vs c2      t        p     양/20
EXP     (절대 setpoint · init 무작위)  6.835   32.00   +0.5433   +8.30   9.6e-08  20/20
abl_mm  (setpoint 완전제거)          1.282   48.23   −5.0095   −2.45   2.4e-02   6/20
abl_mm  (zmu=1.0 만 남김 · 부분누수)    —       —      −0.7576   −1.88   7.6e-02   9/20
Δ(EXP − abl_mm) [setpoint 순기여]                    +5.5528   +2.68   1.5e-02  18/20
```

- **EXP는 init에 완전 불변** — c0 = 0.5·2.0·4.0·8.0·무작위 전부에서 fitness 6.834~6.836, cap_total 32.00, Δ vs c2 = +0.543 (소수 4자리까지 동일). 절대 setpoint의 **복원력 서명**.
- **abl_mm은 init을 흔들면 즉사** — c0=8.0(F4가 말한 "만성 4배 과부하")에서 Δ vs c2 = **−6.98 (t=−66)**, cap 61.5. **F4 PRIMARY의 사망 모드를 그대로 재현**한다.
- `zmu=1.0`이 실제로 setpoint 정보를 나른다는 직접 증거: c0=8.0에서 `zmu=empirical` −27.17 vs `zmu=1.0` −0.69. 즉 **누수 채널이 둘(c0 · zmu0)**.

### PROBE D — 보고된 +0.329는 **지평선(horizon) 인공물**

복원력이 0이므로 레벨은 무한히 표류한다. 보고서의 c0=2.0을 **그대로 둔 채** N만 늘리면:

```
N=1500   cap_abl 34.32   Δ(abl_mm−c2) = +0.329  t= +5.27   (18/20)   ← 보고된 값
N=3000   cap_abl 38.14   Δ(abl_mm−c2) = −0.250  t= −4.80   ( 4/20)   ← 부호 반전
N=6000   cap_abl 46.56   Δ(abl_mm−c2) = −2.448  t=−28.36   ( 0/20)
N=12000  cap_abl 66.03   Δ(abl_mm−c2) = −9.664  t=−41.36   ( 0/20)
(대조) EXP: N=1500→12000 에서 Δ = +0.543 / +0.621 / +0.601 / +0.550, cap 32.0 고정 = 지평선 안정)
```

abl_mm의 용량은 **단조 발산**(32 → 66)하고, 이득은 N=1500~3000 사이에서 부호가 뒤집힌다. 보고서의 N=1500은 공짜 초기화가 아직 소진되지 않은 **딱 그 창 안**이다.

### ⇒ 결론 (2)의 반증

> "z-tonic ablation이 죽지 않고 여전히 최선 상수를 이겨(+0.329) · 이득의 61%는 setpoint 없이 외생 수요 정렬만으로 나온다"

**거짓.** ablation을 올바르게 명세하면(레벨 앵커 제거) z-tonic은 죽는다(−5.01). 61% 분해는 **초기화 공짜점심의 회계**일 뿐이다. **사전등록 조건 (c)("z-tonic ablation 사망")는 사실 충족된다** — 그리고 그 방향은 **F4의 하위주장("절대 setpoint가 원천")을 반증하는 게 아니라 확증한다.** 카드의 파생법칙 「신호 ≠ 컨트롤러」도 그대로 유효하다.
