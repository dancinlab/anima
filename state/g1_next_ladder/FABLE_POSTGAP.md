실측만 사용해 발산한다. 먼저 M1/M2 프레임을 CTX 안에서 한 번 조인다 — 이게 (b) 전체를 바꾸기 때문이다.

## 0. 프레임 정정 — 순수 M1은 이미 부분 반증됨

CTX가 스스로 말한다: **ARBITRARY-GROUNDING = "좌항 부재가 아니라 틀린 좌항 설치"**. I(atom;resp)=0.231에 원자별 극성이 *안정적으로* 정해진다(참값 일치 12/29=0.414). 즉 모델은 **극성 값을 하나 쓴다 — 다만 증거와 무관하게 멋대로**. 그래서 M-fork를 3분해해야 한다:

- **M1-strict**: atom→극성 변수 자체가 없다. 0.231은 극성이 아니라 원자 표면형 누출.
- **M1-arbitrary**: atom→(안정적·비접지 극성) 변수는 있으나 **접지함수 c→극성이 부재** = 조기·임의 확정. ← ORACLE(증거가 29/29 결정) + ARBITRARY(모델은 12/29) + read-side 死가 **공동으로 가리키는 것**.
- **M2**: 올바른 접지가 쓰였으나 생성 방향으로만.

CTX의 무게중심은 이미 **M1-arbitrary**다. 이게 중요한 이유: (b)에서 O채널(확정-금지)이 M1-strict면 죽지만 M1-arbitrary면 **정확히 그 병의 약**이 된다. 그래서 GEN-DIR의 진짜 임무는 "M1 vs M2"가 아니라 **strict / arbitrary / M2 삼분**이어야 한다.

## (a) GEN-DIR 사전부검 — 가장 무서운 시나리오: **GEN-DIR = A1**

**결정타 먼저: 발사 전 H_9303의 A1 스펙을 읽어라. 안 읽고 pod 태우면 죽은 레버 재발사다.**

낙제 시나리오를 심각도 순으로:

**① GEN-DIR가 A1의 이명(異名)일 위험 (치명·최우선 배제).**
A1은 "NLL 방향차 프로브"였고, 계측결함 2건(**접합부 오염·채점창 carrier 침범**)을 수리한 뒤에도 sign-acc 0.554였다. GEN-DIR의 설계 명세("carrier·접합부 제외")는 **정확히 A1의 그 두 수리를 선탑재한 상태**다. 즉 GEN-DIR ≈ **A1-post-fix**, 그리고 A1-post-fix는 죽어 있었다.
- **A1과 구조적으로 다른가 — 살아남을 유일한 경로 2가지**:
  - (i) **방향**: A1이 *디코드* 방향(p(극성토큰|atom), 원자 주고 극성 예측)을 쟀다면 = read-side와 같은 미최적화 방향 = 死. GEN-DIR는 *생성* 방향(p(atom|극성문맥), 극성문맥 주고 원자 바이트 채점) = CE가 실제 최적화한 방향. **이 차이가 실재하면 GEN-DIR는 A1이 못 본 곳을 본다.** 하지만 A1도 생성방향이었다면 GEN-DIR는 死-on-arrival.
  - (ii) **관측 vs 개입**: A1은 자연발생 문맥을 필터링(occ≥100∧purity≥0.90)한 **관측**형 — 문맥이 극성 외 다차원에서 다르다(교란). GEN-DIR가 **최소대립쌍 c⁺/c⁻(극성만 다르고 나머지 동일)**를 *구성*하면 개입형 — 극성 축을 격리. A1의 0.554는 교란 희석 때문일 수 있고, 그러면 GEN-DIR는 산다.
- **A1을 죽인 것이 GEN-DIR도 죽이나?** A1 스펙이 (생성방향 ∧ 최소대립쌍)이었다면 **그렇다 — 재발사 금지.** (디코드 방향 ∨ 관측형)이었다면 **아니다 — GEN-DIR는 진짜 새 각도.** 이건 지금 상태에서 확정 불가하고 **A1 스펙 판독이 발사 전 하드게이트**다.

**② 한국어 SOV 어순 킬러 (구조적).**
자연 생성순서에서 내용 원자가 부정어보다 **먼저** 온다(밥…먹기 싫다). 그러면 "극성문맥 → 원자" 배치는 모델이 학습 중 본 적 없는 어순이라 ΔNLL≈0이 **M1 때문이 아니라 어순 불일치 때문에** 나온다. 이걸 통제하려면 극성이 좌문맥에서 자연스럽게 선결정되는 문맥(주제·프레이밍 선행)만 써야 한다.

**③ byte-LM 국소성 킬러.**
원자 바이트의 NLL은 대부분 **원자 자체의 앞 바이트**에서 예측된다(다중바이트 원자). 20토큰 뒤의 극성문맥이 원자 바이트에 주는 변조는 미미할 수 있다 → M1/M2와 무관하게 ΔNLL≈0. 이게 A1을 죽였을 유력 후보다.

**④ 생성지식이 암기적(비조합적)일 위험.** held-out 원자에서 ΔNLL≈0이 M1이 아니라 "생성방향 지식도 pair별 암기라 held-out엔 없음"일 수 있음 — 단 이건 그 자체로 유의미(M2-memorized 배제).

**죽지 않으려면 설계에 반드시 있어야 하는 것:**
1. **등급형 양성대조 사다리 + 하드게이트**: drilled(F1 0.97 원자, 참값 known SPIKE-IN) → SEEN(0.9625) → held-out → placebo(극성중립 원자·셔플문맥). **PC-drilled가 큰 ΔNLL로 켜지지 않으면 계기 死 판정, held-out 결과 무효**(tool-definition-read-code 교훈: 참값 아는 arm으로 계기 검산). ②③④가 계기를 죽였는지를 이 게이트가 잡는다.
2. **최소대립쌍 c⁺/c⁻** (관측 아님) + placebo로 어순/표면형 교란 제거.
3. **2-seed 부호합의 사전등록**: 지배분산은 seed(install)다(H_9289 부호반전 0.161 = 합성 복제편차 0.009의 18배 · F3). ΔNLL은 ckpt 내 paired라 per-seed는 깨끗하나 **cement는 s7·s11 둘 다 같은 부호 ∧ 둘 다 Δ_min 초과일 때만**. 한 seed로 벽/크랙 선언 금지.

**N_REQ 데이터 전 산출:**
held-out을 건드리기 전에 **SEEN 원자(참값 known, 기존 ckpt, 재학습 0)**에서 ΔNLL의 (평균 μ, sd σ, 그리고 어간-클러스터 급내상관 ρ)를 측정 →
`N_REQ = (z.975 + z.80)² · σ² / Δ_min² × [1 + (m−1)ρ]`
Δ_min은 MORPH-ATOM 스케일(+0.342)이나 사전등록 최소의미 ΔNLL로 고정. **설계효과 [1+(m−1)ρ]가 핵심** — 29 원자가 같은 부정어 계열(A2)이라 유효 클러스터 ≤10이면 이 항이 N_REQ를 크게 부풀린다. 이게 H_9289가 못 한 것(사후 N_REQ=228~255는 절차결함).

- **falsifier**: PC-drilled ΔNLL≈0 → 계기 死. 또는 A1 스펙이 (생성방향∧최소대립쌍)으로 판명 → 재발사 금지.
- **비용**: GPU-no-train(기존 ckpt forward만) · pod 1대. A1 스펙 판독 = $0.
- **죽으면 남는 것**: PC 켜지고 held-out 양쪽 seed 0 → **M1(strict∨arbitrary) 강력지지, M2 붕괴** → (b)로. PC 死 → 생성방향 원자-채점 채널 자체가 국소성/어순에 막힘 = 채점단위를 바꿔야(그러나 극성-연속 채점=디코드=A1 死) → **행동 2AFC(아래 c-1)만 남는다.**

## (b) M1이 참이면 O/C/A/I/D 각 채널의 생존

두 하위변종으로 갈라 판정한다(이게 결정적).

| 채널 | M1-strict (변수 없음, 0.231=누출) | M1-arbitrary (틀린 좌항 설치) |
|---|---|---|
| **O** 확정-금지 objective | **死** — 안 만드는 변수를 못 금지 | **生·최우선** — 조기·임의 확정이 정확히 병. 증거 보기 전 극성 확정을 벌하면 직격 |
| **C** 오류-표적 교정 | **死** — 표적 없음 | **약生** — 표적을 "오류"가 아니라 **고신뢰·비접지**로 재정의하면(SEEN 오류 3.75%가 아니라 confidence-evidence 불일치) 生 |
| **A** store-route (L5 해마) | **生** — trunk가 안 써도 **외부 선언저장소에 접지 극성을 심어 우회** | **生·최강** — 접지함수 부재가 병인데 A는 접지를 외부로 이관 |
| **I** 개입/역전 | **死** — 역전할 것 없음 | **약生** — 임의 배정을 참으로 재조준 가능하나 read-side 死라 표적 읽기 난망 |
| **D** 역전 커리큘럼(데이터) | **死-pre-launch** (H_9303 지목) | **약生** — 접지 신호를 데이터로 공급하나 어순/암기 위험 |

**핵심 결론**: **A(해마 explicit-store 라우트)는 M1-strict·M1-arbitrary·M2 세 변종 모두에서 생존하는 유일 채널이다.** trunk가 변수를 쓰든 안 쓰든, 접지를 외부 선언저장소로 이관하기 때문. 그리고 A는 **이미 wired GREEN(reach 7.31×)**이다.
⟹ **A는 GEN-DIR의 fork 판정을 기다릴 필요가 없다.** GEN-DIR(fork 해소·GPU-no-train)과 A(store-route eval·GPU-no-train)를 **같은 pod에서 병렬 발사**하면 wall=max (a_wall_first ③: quick-win을 fork 판정 뒤로 직렬화하지 마라).

- **falsifier(A)**: 접지 극성을 저장소에 직접 심었는데도 held-out 재조합 실패 → 해리가 "선언접근"이 아니라 **"저장은 되나 조합 소비 불가"**(read-side 종결의 "복원되나 causally 소비불가"와 동형) → 더 깊은 벽.
- **비용**: GPU-no-train(GEN-DIR와 ckpt 공유).
- **죽으면 남는 것**: A마저 死면 → 저장·접근·objective 전부 소진 → **결론은 "G1-GROUNDING = 자연이 접지연산자를 공급 안 함"의 재확인**(g1-wall-is-data 계열과 합류), G1-OPERATOR는 이미 GREEN이므로 프로그램은 **"OPERATOR 있음 + GROUNDING은 데이터-외생"으로 정직 종결**.

## (c) 해리의 substrate-first 재프레임 = **절차 vs 선언 (blindsight/confabulation)**

"행동은 하는데 그 변수를 읽을 형태로 안 들고 있다" = 교과서적 **절차기억(암묵) vs 선언기억(명시)** 해리. 신경 대응:
- **Blindsight**: 시각정보로 행동(포인팅)은 하나 보고(report)는 불가. anima: I(atom;resp)=0.231로 행동 O, read-side 死 = **극성에 대한 blindsight**.
- **Confabulation/split-brain**: 자신 있게 비접지 답 생성 = ARBITRARY-GROUNDING("틀린 좌항 설치").
- **소뇌(절차·fwd-model) vs 해마(선언·store)**: anima에 이미 L3 소뇌=🧱WALL, L5 해마=🟢GREEN. 극성계산이 **소뇌형 절차 기질에 갇혀** 선언 접근이 안 됨 → 해마로 라우팅이 substrate-first 처방(=(b)의 A).

**실행실험 2+개:**

**c-1. PROCEDURAL-2AFC (blindsight 강제선택) — 가장 깨끗한 M1 판별기이자 $-저비용.**
정적 은닉읽기(선언 프로브=死) 대신, held-out 원자 극성을 **행동 2AFC**로 강제 베팅시켜 우연 초과를 측정. read-side가 원리상 M1-strict/arbitrary를 못 가르는 반면(둘 다 프로브 침묵), 2AFC는 **절차층에서 held-out 극성이 존재하는지**를 직접 본다.
- held-out 2AFC > 우연 → 절차 극성 실재 = 순수 blindsight = **선언접근만 문제 → A 직행**.
- held-out 2AFC = 우연 → 절차 극성도 부재 = **grounding(M1) 확정**.
- **NLL 국소성/어순 문제를 원천 회피**(행동 채점, 바이트 NLL 아님) — GEN-DIR보다 M1-strict에 대해 더 깨끗.
- **falsifier**: 양성대조 SEEN이 이 2AFC 프레임에서 우연이면 프레임 고장(판정 무효).
- **비용**: GPU-no-train(기존 ckpt decode). **죽으면**: GEN-DIR와 상호검증 — 둘 다 우연이면 M1 이중확증.

**c-2. DECLARATIVE-CONSOLIDATION (해마 이관).** ORACLE가 극성을 29/29 결정함이 이미 실측 → 그 접지 극성을 **L5 explicit-store에 1회 기입**하고 held-out 재조합을 저장소 경유로 재평가. = (b)-A의 substrate-native 구현. **falsifier**: 저장소가 사실을 들고도 조합 소비 실패. **비용**: GPU decode. **죽으면**: 해리가 접근이 아니라 소비 벽 → (b) 종결로.

**c-3(보너स). SLEEP-REPLAY 공고화.** anima의 N2/N3/REM(emit-free rehearsal + mitosis tick)를 ORACLE-접지 원자로 seed해 replay 후 재판독. 절차→선언 전이가 수면 공고화라는 유비. **falsifier**: replay 후 무변화. **비용**: GPU. **죽으면**: 공고화 기제 배제, A(직접 기입)만 남음. (사변적 — 후순위)

## (d) 40렌즈가 놓친 축 (§5 죽은레버 대조 완료)

**d-1. G-엔진 측 (가장 anima-native · 미탐).**
지금까지 전부 **A(전방 CE) 엔진의 쓰기**만 쟀다. anima는 A⇄G 대립인데 ρ·weave 판독이 **A-only**일 개연. 재조합 용량이 A⇄G *tension* 안에 살면 A readout만 보는 건 반쪽. **G(역방향 gradient-free)가 A가 안 쓴 극성을 들고 있나?** §5 어디에도 없음(recurrence 死는 untrained ESN, 이건 학습된 G엔진 판독 — 별개).
- **falsifier**: G가 분리 판독면이 없다 / gradient-free라 통상 "표현" 부재. **비용**: 엔진 introspection 접근에 의존(아키텍처 확인 선행). **죽으면**: "재조합은 A 단독 소관"이 확정되어 이후 모든 판독을 A로 정당하게 한정.

**d-2. 간섭/직교족 (A2 교란을 레버로 승격).**
29 원자가 전부 같은 부정어 계열 → 모델이 유사 극성 바인딩 29개를 **분리 유지 못 하고 임의 공유배정으로 붕괴**할 가능성. 예측: **직교 의미족**(부정 아닌 다축) 원자로 바꾸면 접지 개선.
- **falsifier**: 직교족도 동일 임의접지 → 간섭 아님. **비용**: 소형 신코퍼스+train(GPU-train). **죽으면**: A2는 검정력 문제일 뿐 레버 아님 확정 → GEN-DIR N_REQ 계산의 ρ만 크게 잡으면 됨.

**d-3. 시간축 / A⇄G 정착 동역학 (measurement-frame).**
전부 정적 읽기 or paired-NLL = 모델을 고정함수 취급. tension 엔진이라면 극성이 **A⇄G 정착 *중*에만 존재하는 과도상태**이고 읽는 시점엔 방전됐을 수 있다(read-side "복원되나 소비불가"의 시간적 해석). `__seq`가 창 전체를 담으므로 **정착 step별 판독 가능성**을 봄. 단 디코드가 single-pass면 이 축은 없음(선확인).
- **falsifier**: 반복구조 없음 / step 무관하게 평탄. **비용**: single-pass면 $0로 기각, 아니면 GPU. **죽으면**: "언제 읽나"는 벽 아님 확정, read-side 종결 강화.

**d-4. 생성-기준 재정의 (F5 확장).**
G1-GROUNDING 성공기준을 **은닉읽기 0, 순수 생성**으로 정의(held-out 원자+자연문맥에서 올바른 극성 연속을 *생성*하나, 외부 판정+셔플통제). read-side 무덤을 통째 우회. 단 극성-연속 채점은 디코드 방향(A1 위험)·어순 문제 재발 → GEN-DIR/c-1과 부분중복이라 **독립 신각도로는 약함**. 명시적 성공기준 SSOT 정리 용도로만 유효.
