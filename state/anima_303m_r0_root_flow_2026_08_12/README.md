# 303M meaningful-conversation root-flow recovery

Status: `ENGINE-ROOT-FLOW-RECOVERED`; the existing 303M checkpoint verdict remains
`FAIL-MEANINGLESS-REPETITION` and R1/production remain locked.

This recovery fixes the shared Python path before another GPU run. It does not alter the frozen
conversation panel, failed checkpoints, historical data revisions, random seeds, thresholds, or
past verdicts.

## Confirmed shared causes

1. Dataset/evaluation used `user: …\nassistant:`, while `anima-py chat` used a separate Korean
   role frame and 96 generated bytes. The participant used another 80-byte budget.
2. The evaluator loaded the same checkpoint but reimplemented greedy decode below
   `core.generator`, so evaluation and serving did not share one mouth contract.
3. Response CE found `assistant:` payloads in arbitrary byte windows without requiring the
   corresponding user prompt to remain visible.
4. The semantic scorer counted negated English concepts and arbitrary Hangul substrings as
   positive evidence.
5. Intermediate ByteGPT serializer metadata recorded configured final steps and train CE instead
   of the actual completed step and validation CE.
6. The production participant's serialized mouth adapter accepted `.clm` only even though the
   canonical generator already supported ByteGPT `.bin`.

## Recovery

- `core/generator.py` now owns the role prefixes, turn separator, role-boundary parser and
  192-byte generation budget. Builder, evaluator, CLI chat and participant validate or consume
  that contract.
- Evaluation and participant serving call the same loaded-mouth generator entry for `.clm` and
  `.bin` while keeping weights resident.
- `anima-py train --chat-framed-sampling` extends the existing `ByteCell` sampler and is accepted
  only with canonical all-span response CE. Dialogue cells then sample complete documents that fit
  the causal window; eligible, oversize and realized framed-window counts are preserved in the
  summary and exact-resume state.
- The dataset builder preserves `messages`/`conversations` multi-turn trajectories and can fail
  before publication when a protocol's per-language minimum multi-turn mass is absent.
- Panel SHA-256 can be enforced with `--conversation-panel-sha256`; mismatch fails before model
  loading. Negated concepts and Hangul substring hits no longer certify semantic relevance.
- ByteGPT bridge metadata now receives the actual completed step and latest measured validation
  CE. The participant adapter header-sniffs and serves `.clm` or ByteGPT `.bin` through the same
  dispatcher.

## Remaining gate

No new 303M model was trained or deployed. A new immutable HF `dancinlab` data revision still
needs a provenance-safe Korean multi-turn source. Sources found during the audit were not silently
adopted: the available candidates were synthetic/persona-shaped, non-commercial, ambiguously
licensed, or too small/misaligned. The next executable R0 must pin an acceptable source, require
nonzero English/Korean multi-turn coverage, use canonical framed sampling, and pass the unchanged
meaningful-conversation gate before R1 or production.
