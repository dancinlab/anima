# IIT daemon R3.6 — learned semantic bridge microexperiment (2026-08-15)

Status: COMPLETE — `FAIL-LEARNED-SEMANTIC-BRIDGE`.

R3.5 proved that a persistent IIT state can select an externally supplied entity/relation/value
record and route it to canonical bytes. It did not learn that record from input. R3.6 changes one
shared axis only: the evaluator-authored record is replaced by a deterministic learned encoder at
the existing input boundary. The IIT transition, three addresses, delayed latch, workspace,
renderer, R3.5 nine-trial panel and causal bars stay fixed.

## Fixed question and call flow

```text
bounded UTF-8 event bytes
  -> core.iit_daemon semantic bridge (learned factorised byte n-gram centroids)
  -> validated address + entity/relation/value record
  -> existing content workspace
  -> existing IITDaemonCore address latch and delayed transition
  -> existing core.generator.gen_iit_workspace_content
  -> canonical response bytes
```

The bridge is trained from labelled support events generated by `panel.json`. Training covers every
address and every entity/relation/value atom and every registered relation surface, but excludes
every complete record used by the R3.5 evaluation arms. Evaluation uses held-out sentence frames
and novel atom combinations. The model is a factorised nearest-centroid classifier over the
existing canonical `core.mi_compress.hashed_ngram_features`; it contains no question-to-answer
rules, parser dictionary, prompt lookup or gold output field. Common template features cancel
between class centroids while address and record fields are learned independently.

## Design exhaustion and exclusions

| Variant | Decision | Reason |
|---|---|---|
| Reuse evaluator-authored records | reject | repeats the R3.5 oracle seam and cannot test input grounding |
| Add regex or a fixed grammar parser | reject | would encode the answer in programmer-authored rules |
| Train another ByteGPT mouth | reject for this gate | prior mouth failures would confound bridge causality and consume GPU time |
| Add a tokenizer/BPE/BLT patcher | defer | changes representation and architecture together |
| End-to-end IIT/mouth joint training | defer | failure would not identify whether grounding, memory or decoding broke |
| Learned whole-triple class | reject | cannot represent unseen entity/relation/value compositions |
| Factorised byte n-gram centroids | choose | deterministic, CPU-small, learned, compositional and reuses the Python feature engine |
| Let expected bytes enter the bridge | reject | evaluator shortcut around the causal path |
| Online public-chat weight updates | reject | provenance loss and persistent prompt poisoning |
| Same fitted bridge with state/store interventions | choose | parameter-, data- and exposure-matched causal controls |

This is intentionally not a new mouth, engine or evaluation program. It extends the existing
`anima-py evaluate` R3.5 path. External I/O remains UTF-8 bytes and the canonical renderer remains
the only output boundary.

## Frozen protocol

`protocol.json` and `panel.json` are the SSOT. The R3.5 result and panel are checksum-pinned. The
panel fixes atoms, relation surfaces, support/evaluation frames, negative events and query frames.
Support examples are the deterministic cross-product minus all evaluation records; no seed or
sampling is used.

The evaluator runs in this order:

1. R3.5 state/address oracle;
2. learned event-kind, query-address and complete-record held-out accuracy;
3. normal held-out paraphrase/composition episodes;
4. stateless store control;
5. IIT state reset before delayed read;
6. IIT intervention-address shuffle;
7. workspace address shuffle;
8. all-node lesion;
9. selected-record counterfactual memory;
10. irrelevant-record mutation;
11. correction of an earlier memory;
12. exact snapshot disturbance and recovery.

The state oracle and every learned bridge accuracy must be at least `0.90` before later arms are
interpreted. Normal, correction and recovery must be at least `0.90`. Stateless, reset, both
shuffles and lesion must be no higher than measured three-way chance plus `0.06`, namely
`0.393333...`. Selected-memory counterfactual change and irrelevant-memory stability must each be
at least `0.90`. The same question with a changed selected memory must produce the newly correct
bytes; changing an irrelevant memory must preserve the output byte-for-byte.

Bridge failure returns `FAIL-LEARNED-SEMANTIC-BRIDGE` and blocks downstream interpretation. A full
pass returns `SUPPORTED-LEARNED-SEMANTIC-BRIDGE-CAUSALITY`. No panel row, atom, surface, training
frame, exclusion, model dimension, threshold or arm may change after results are read.

## Non-claims and stop condition

A pass would show only bounded learned conversion from registered English event surfaces into
compositional records whose persistence causally controls canonical bytes. It would not establish
open-domain semantics, a conversational mouth, Korean support, spontaneous goals, phenomenal
consciousness, IIT exclusion/maximal complex or production readiness. Production remains
`BLOCKED-R36-NOT-A-CONVERSATIONAL-MOUTH` regardless of this microexperiment. A failure is recorded
as observed; it does not authorize threshold, panel, seed or support-set tuning.

## Result

The frozen first execution failed at the learned bridge gate, so the later causal arms were not
run or interpreted.

- R3.5 state/address oracle: `1.0000`.
- Held-out event-kind accuracy: `38/47 = 0.8085106`, below `0.90`.
- Held-out query-address accuracy: `0/9 = 0.0000`, below `0.90`. All nine held-out query frames
  were classified as `other`, so no address was emitted.
- Held-out complete address+record accuracy: `25/36 = 0.6944444`, below `0.90`.
- The deterministic support expansion produced 702 labelled events after excluding all 35 complete
  records used by the R3.5 normal/counterfactual/irrelevant arms.
- The learned model checksum is
  `49b4184419f6aa10df3fc3bc59f6099c8de32087b74f7733c33e941c7cc56355`; atomic serialization and
  reload are exact and mode `0600`.
- Because the bridge gate failed, normal/stateless/reset/IIT-shuffle/workspace-shuffle/lesion/
  counterfactual/irrelevant/correction/recovery results do not exist. This is required gate order,
  not missing reporting.

The failure localizes the current wall before IIT selection: a bag-of-byte-n-gram centroid sees
the registered training surfaces but does not reliably factor held-out event type and record
fields. It is not evidence against the already-passed R3.5 workspace, and it does not authorize
retuning this frozen panel. The next experiment must be separately preregistered and compare an
order-aware learned event encoder against this exact failed control.
