# H_9300 — 사전등록 (FROZEN 2026-07-14 · win=192 재측정 결과를 보기 **전에** 커밋)

## §0 발견 — 오라클과 모델이 **본 것이 다르다**

프런티어의 사슬은 이 대비 위에 서 있다:

```
오라클 (H_9291)  같은 좌문맥으로 held-out 29 원자 극성 29/29 = 1.000 복원
모델   (H_9297)  그런데 표현에서는 못 읽는다 (n=91 · bar 2.86σ · 0.527/0.505)
      ⇒ 정보는 입력에 있는데 표현에 없다  ⇒  벽 = 추출 채널  ⇒  O/C 채널
```

**그 대비가 성립하지 않는다.** `anima-py evaluate --dump-hidden` 의 사양(evaluate.py L1112 verbatim):

> "For each pre-registered prompt: **T=24 right-aligned byte encode** → the EXACT production trunk
> forward → per-position yn:[T, d]"

즉 `--win 24` 는 **24 바이트** = **한글 약 8자**다. 그런데 `gt_prompts` 의 프롬프트는
**중앙값 49 byte · 최대 190 byte** 이고, 오라클은 그 **전체 64자** 를 읽었다.

**모델의 dump된 표현이 실제로 본 것 (실측):**
```
프롬프트 156 byte / 64자  →  오라클이 읽은 것: 전체 (극성 증거 "배송도 빠르고…" 포함)
                          →  모델이 본 것:    "…될 때 까지 숨 참"   ← 마지막 8자뿐
```

**극성 증거는 문맥의 앞부분에 실린다**(H_9291 이 규명한 기제: "긍정 원자는 '리얼좋아요/배송도
빠르고/가성비는 좋아요' 이웃 속에"). 그 앞부분을 **모델의 표현은 애초에 보지 못했다.**

⇒ **H_9297 의 EARNED 음성은 "모델이 극성을 인코딩 못 한다" 가 아니라 "24 바이트만 준 표현에
   극성이 없다" 일 수 있다.** 오라클은 ~150 byte 를 읽었다. **10배 차이의 불공정 대비.**

**부수 신호 (A7 · 감성 축 바닥 · win=24):** 모델은 그 창에서 **리뷰 전체의 긍/부정조차** 못
가른다 (best 0.545 · n=200 · +1.3σ · p=0.115). 감성 축이 아예 안 보인다 — 24 byte 로는 당연하다.

## §1 물음 — 창을 열어주면 극성이 나타나는가

> **모델에게 오라클과 같은 문맥을 주면(win = 전체 프롬프트), held-out 원자의 극성이 표현에서
> 읽히는가?**

읽힌다면 H_9297 의 EARNED 음성은 **철회**되고, 프런티어의 "벽 = 추출 채널" 진단과 그 위의
O/C 채널 설계는 **근거를 잃는다**. 안 읽힌다면 H_9297 은 **더 강해진다**(창 confound 를 배제한
채 재확인).

## §2 방법 — **창 하나만** 바꾼다

H_9297 에서 그대로 동결(1바이트도 안 움직임): frozen ckpt 4 arm · `gt_prompts_n92.json`(동일
프롬프트) · 원자 split(train 20 / held-out 91) · **bar 0.65** · 프로브(P-LIN primary · L2-logreg ·
평균풀링) · 200회 라벨-순열 귀무분포 · seeds.

**바꾸는 것:** `--win 24` → **`--win 192`** (프롬프트 최대 190 byte 를 전부 담는다).

**검정력 (변동 없음):** n=91 · 우연 sd 0.0524 · **bar 0.65 = 2.86σ**.

## §3 상시 V-게이트

- **V-WINDOW (신규 · 이 H 의 전제)** — win=192 에서 프롬프트가 **잘리지 않아야** 한다
  (max prompt 190 ≤ 192). 실측 보고.
- **V-CONTRAST (신규 · 결정적)** — **같은 프로브를 win=24 로도 돌려 H_9297 을 재현**해야 한다
  (0.527/0.505 ± 0.05). 재현 실패 = 파이프라인 불일치 ⇒ 어떤 수치도 읽지 않는다.
  ⇒ 두 창의 **차이만이** 이 H 의 신호다.
- **V-FIT** — train_fit ≥ 0.90. ⚠️ **개정 II 로 무효화됨** (아래 V-CV 로 대체).
- **V-PERM** — 200회 라벨-순열 귀무분포 백분위 (밴드 아님).
- **V-BASE** — `base_only` arm 은 bar 미달이어야 한다.

### 개정 I — RF 반증 (결과 개봉 前 · 2026-07-14 07:35)

/gap 의 F1 렌즈가 소스에서 "trunk = causal dilated CNN(K=3·L=4·dil 1-8) ⇒ `__last` 의 수용영역 =
**35 byte** ⇒ `--win 192` 는 `__last` 에 아무것도 더 넣지 못한다(win≥35 에서 비트동일)" 를 유도했다.
**직접 인과 측정으로 반증**(`rf_probe.json` · 180B 균일 프롬프트에서 끝-거리 d 의 바이트 1개만 flip):

```
d=  5B → max|Δ| 6.86 MOVES     d= 64B → 1.19 MOVES
d= 34B → 1.16 MOVES            d=120B → 2.29 MOVES
d= 36B → 2.26 MOVES            d=170B → 2.20 MOVES   ← 35B 벽 없음
```
⇒ `__last` 는 창 전체를 본다. **§1·§2 의 전제는 유효**하고 이 H 는 그대로 진행한다.
(교훈: 소스 유도 ≠ 실측. RF 는 인과 flip 으로 재는 것이다.)

### 개정 II — V-LENGTH (신규 · 주장에 **불리한** 통제 추가 · 결과 개봉 前)

**bar 는 1바이트도 안 옮긴다**(0.65 동결 유지). 대신 이 H 를 **더 어렵게** 만드는 통제를 추가한다
(tune-to-green 의 반대 방향이므로 허용 · `control-must-match-mediating-covariate`).

**발견한 교란**: held-out 91 원자에서 프롬프트 **바이트길이 ↔ 극성** r = **−0.301**. 그리고 win=192
는 짧은 프롬프트를 **공백 127B 평균**으로 left-pad 하므로 길이가 표현에 직접 새어든다. 실측 —
**특징을 길이 하나만 준 프로브**를 실제 파이프라인 그대로(train n=20 적합 → held-out n=91 시험)
돌리면 **held-out 0.648 (+2.83σ)** = **동결 bar 0.65 에 사실상 도달**한다. (train 자체에는 길이-극성
상관이 없다(r=−0.016) — 20점 적합의 잡음 방향이 held-out 의 실제 누수에 올라탄 것이다.)

⇒ **bar 0.65 는 교란 바닥 위에 있지 않다.** 통과해도 극성인지 길이인지 구분이 안 된다.

- **V-LENGTH-A (결정적)** — 모든 arm 의 held-out 수치와 **함께** `LENGTH-ONLY` 기준선(0.648)을
  보고한다. 실험 arm 이 이 기준선을 **넘지 못하면** 어떤 상승도 극성 증거로 읽지 않는다.
- **V-LENGTH-B (결정적)** — 주 프로브를 **길이-잔차화**(hidden 특징을 프롬프트 평균 바이트길이에
  회귀시켜 잔차로 재적합)해서도 함께 보고한다. **잔차 프로브가 bar 를 넘어야** 🔓/🟡 를 읽는다.
  넘지 못하면 판정은 **⏳ LENGTH-CONFOUND (tier 미보고)** 이지 음성이 아니다.
- **V-CV (V-FIT 대체)** — train n=20 · d=768 이라 `train_fit=1.000` 은 **모든 arm 에서 수학적으로
  자명**(20점은 항상 분리된다) ⇒ 게이트 기능 0. train 20 원자의 **leave-one-out CV** 로 대체한다.
