THE FIX (the only change vs H_1318 — everything else byte-identical)
--------------------------------------------------------------------
Decompose each Han character into its IDS (Ideographic Description Sequence)
sub-character COMPONENTS — the real structural leaves — with NO full-char
residual token (the exact bug that broke H_1318).

  Decomposition SOURCE (REAL, deterministic, recoverable):
    CHISE IDS Database, distributed as `cjkvi/cjkvi-ids` (file ids.txt), the
    canonical community CJK Ideographic-Description database (88,937 entries).
    Format per line: `U+XXXX <TAB> char <TAB> IDS-string`, where the IDS string
    is the Ideographic Description: Ideographic Description Characters
    (IDC: ⿰⿱⿲⿳⿴⿵⿶⿷⿸⿹⿺⿻) compose component leaves, e.g.
        語 → ⿰言吾     (leaves 言, 吾)
        明 → ⿰日月     (leaves 日, 月)
        字 → ⿱宀子     (leaves 宀, 子)
        日 → 日         (atomic: single leaf == self)
    Fetched at run time from the public GitHub raw URL
    `https://raw.githubusercontent.com/cjkvi/cjkvi-ids/master/ids.txt`,
    cached to disk, sha256 of the IDS file asserted + recorded. NO credential.

  DECOMPOSITION RULE (FROZEN — one level, leaves only, no residual):
    For each Han codepoint (CJK Unified 0x4E00-0x9FFF or Ext-A 0x3400-0x4DBF):
      1. look up its IDS string;
      2. STRIP all IDC operators (⿰…⿻), all entity refs `&...;`, all region
         tags `[GTKV...]`, and whitespace; the remaining characters are the
         COMPONENT LEAVES (one TOP level of the IDS, NOT recursive — deterministic
         and modest);
      3. the Han char becomes EXACTLY that leaf sequence — NO full-char residual
         symbol is ever emitted (the H_1318 bug is removed);
      4. if a char is atomic (its only leaf is itself, e.g. 日, 人, 山) it stays
         as ONE component symbol == that char (honest: an atomic char exposes no
         composition — it contributes no decomposition signal, which is correct);
      5. if a char is absent from the IDS DB (expected ~0 on Han basic+ext-A),
         fall back to atomic (the char itself), counted + reported.
    Non-Han characters (kana, Latin, punctuation, digits) pass through unchanged
    as raw UTF-8 bytes — identical to H_1318.

  EXPECTED MODEST VOCAB (the whole point — measured on the real 200 KB smoke
  windows; FREEZE states the 30 MB numbers will be recorded in the run, and IF
  vocab still explodes that is itself the honest finding):
    smoke 200 KB: zh 2172 distinct Han chars → 1072 components (vs H_1318 9327);
                  ja 1274 distinct Han chars →  784 components (vs H_1318 4738).
    ~88% of Han tokens decompose into ≥2 components (avg ≈ 2.0 comps/char);
    ~11–13% are atomic. IDS-miss = 0 on the smoke sample.

  BYTE ACCOUNTING (load-bearing — preserves the FAIR CE-per-byte axis):
    each Han char of UTF-8 length blen contributes its component symbols whose
    per-symbol n_bytes SUM to blen (spread blen across the leaves; first leaf
    carries the remainder). So Σ n_bytes over the STRUCT stream == the raw UTF-8
    byte count of the held-out text, IDENTICAL denominator to RAW — exactly the
    H_1318 fair-axis invariant. Unlike H_1318's Han path (radical = 0-byte leading
    marker + residual = full blen), here the bytes are spread across the real
    leaves; the denominator (held-out raw UTF-8 bytes) is unchanged either way.
