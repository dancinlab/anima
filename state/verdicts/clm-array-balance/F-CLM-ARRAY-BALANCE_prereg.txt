MOTIVATION (re-approach of H_878 🔴):
  H_878 showed that a STATIC HASH partition of the E sparse experts across N
  MITOSIS chips (even contiguous shards, expert -> fixed chip by index) leaves
  the per-chip token load badly IMBALANCED, because the trained top-k router
  monopolizes a few experts (max/min per-chip dispatch ratio 1.88 -> 28.8 ->
  54.5 for N=2,4,8, far over its bound). H_885 tests whether a CAPACITY-AWARE
  re-partition (assign experts to chips by MEASURED per-expert usage so each
  chip's aggregate load is balanced — a longest-processing-time / greedy bin-pack
  on a profiling split) FIXES the imbalance WITHOUT hurting aggregate output
  quality (the gather is still a disjoint re-association of the SAME experts and
  the SAME router weights, so coherence must be preserved exactly).

SCOPE (a_scale_honest_scope · a_paper_negative_ok):
  SW-SIMULATION ONLY of the deploy chip-fit track, identical scope to H_878. NO
  silicon: exactly one physical AKD1000 today (rest is pi5/1-chip). We simulate
  the N-chip array in software. The capacity-aware re-partition is computed from
  a held-out PROFILING split (disjoint from the eval split) so the assignment
  does NOT peek at the eval tokens it is scored on. NOT measured: chip-to-chip
  DMA latency / silicon timing / real-chip int4 emit drift (HW follow-up).

LOAD METRIC (chosen BEFORE run): per-chip dispatch-count COEFFICIENT OF VARIATION
  CV = std(chip_counts) / mean(chip_counts)   (population std; over the N chips).
  CV = 0 is perfectly balanced; CV grows with imbalance. CV is scale-free and the
  metric named in the H_885 candidate row ("per-chip load CV"). Reported per N,
  mean over seeds, for BOTH arms (static-hash = H_878 baseline; capacity-aware).

ARMS:
  (S) STATIC-HASH  — the H_878 partition: even contiguous shards, expert e -> chip
                     e // shard_size. The frozen H_878 baseline.
  (C) CAPACITY-AWARE — profile per-expert top-1 dispatch counts on the PROFILING
                     split, then greedily assign experts (descending profiled load)
                     to the currently-least-loaded chip (LPT bin-pack), so each
                     chip's expected aggregate load is balanced.
