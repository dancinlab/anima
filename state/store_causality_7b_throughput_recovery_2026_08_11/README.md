## Diagnostic and decision order

1. load the exact checkpoint and reproduce the fixed 20-emission failure once on a full H100 PCIe;
2. profile the existing per-byte call path, separating trunk convolution, normalization, MoE,
   readout, device-to-host synchronization, Python orchestration, and WebSocket serialization;
3. identify the shared runtime cause. If it is not localized, record the failure and stop;
4. make only the smallest canonical runtime correction. Generated bytes and logits must remain
   equal to the pre-change path on fixed fixtures; no reduced precision or alternate decoder is
   allowed merely to clear the throughput bar;
5. run Python regression, loader checks, Torch↔NumPy CLMS parity, and the fixed 20×32-byte panel;
6. require rho-form `>=0.70`, then pair-oracle `>=0.90`; only a pair-oracle pass unlocks normal →
   clue-A removal → clue-B removal → address shuffle → exact recovery;
7. only a complete causal pass plus minimum throughput `>=2.0 bytes/s` unlocks HTTP/WebSocket,
   peak-VRAM, 30-minute soak, failure recovery, and AKIDA rollback;
8. upload any changed model/checkpoint artifact only to private HF `dancinlab`, record every result
   without a result-dependent retry, delete the Vast.ai instance, and commit/push the evidence;
9. only if every registered gate passes, deploy the existing 7B participant to production and
   verify `https://chat.dancinlab.org` HTTP, WebSocket, generation, and `anima_alive=true`.

The likely cost center visible from source inspection is not yet a verdict: each emitted byte runs
a fresh length-24 trunk and full-position readout before copying logits to the host. The profile in
step 2 must determine which shared operation is actually responsible before code changes are made.
