## §2 — on-chip learning: the exact §95 mechanism

§95 classified Akida 1.0 as `INFERENCE-ONLY-BLOCKED`. The primary docs sharpen *why* — the on-chip learning that BrainChip markets is **the narrowest possible kind**:

> *"The AKD1000 device supports on-chip continual learning for the last layer only. The layer must be FullyConnected, it must have binary weights, and receive binary inputs."*
> — Open Neuromorphic spec writeup, citing BrainChip MetaTF docs

Three load-bearing constraints, all simultaneous:

1. **Last layer only** — the rest of the network is frozen post-conversion. The chip cannot adapt features, only the output classification head.
2. **Fully-connected only** — no convolution, no attention, no recurrent learning on chip.
3. **Binary weights AND binary inputs** — single-bit precision; cannot learn fine-grained adjustments.

No backpropagation is supported. The on-chip rule is BrainChip's proprietary local learning rule (Akida calls it "edge learning"), used for **few-shot / 1-shot incremental classification of new classes** on top of a frozen GPU-pretrained backbone.

§95's `INFERENCE-ONLY-BLOCKED` is verified — and slightly *tightened*: it's not just "inference-only," it's "inference + a single-binary-FC-layer edge-learning patch on top." For anima's `§11-B-as-substrate` question (does a non-GPU substrate decide whether `CE is load-bearing`?), this learning channel is too narrow to count. It cannot host **training-time emergence** in the §11-B sense (no end-to-end gradient or end-to-end local-plasticity flow through the network).

## §3 — toolchain (MetaTF) — what models the chip actually accepts

| Stage | Component | Function |
|---|---|---|
| Train | **standard Keras / TensorFlow** | regular GPU training (CE / backprop / whatever) |
| Quantize | **`quantizeml`** (BrainChip Python pkg) | quantize Keras model to ≤ 8-bit weights/activations |
| Convert | **`CNN2SNN`** (BrainChip Python pkg) | convert quantized ANN → spiking representation Akida-runtime understands |
| Deploy | **MetaTF runtime** on AKD1000 | event-driven inference + optional binary-FC edge-learning |

Honest reading: the AKD1000 pipeline is **"train ANN on GPU → quantize → translate to spiking → run."** The chip is **not** a from-scratch training substrate; it is an event-driven *inference accelerator with a tiny adapter for incremental classification.* This is exactly what §95's `INFERENCE-ONLY-BLOCKED` bucket says.

The toolchain primary input class is **CNN-based vision / keyword models** (AkidaNet, MobileNet-class, FOMO, image classification). Edge Impulse provides an official integration for the dev workflow.

## §4 — model class support (AKD1000 vs AKD2000 — critical disambiguation)

| Class | AKD1000 (1st gen, 2022) | AKD2000 (2nd gen) |
|---|---|---|
| CNN | ✅ supported (Akida 1.0 layer types) | ✅ |
| DNN (small fully-connected) | ✅ | ✅ |
| RNN | ✅ (limited) | ✅ |
| **Vision Transformer (ViT)** | **✗ not supported** | **✅ accelerated** (2nd-gen feature) |
| **8-bit weights/activations** | ✗ (4-bit + binary on Akida 1.0) | ✅ |
| Multi-pass sequential processing | ✗ | ✅ |
| Configurable local scratchpads | ✗ | ✅ |

> *"AKD1000 and AKD1500 devices support only Akida 1.0 layer types, of which there is only a limited number."*
> — Open Neuromorphic spec writeup

**Implication for anima**: anima's ConsciousDecoderV2 is a **byte-vocab transformer** (RoPE + SwiGLU + RMSNorm + GQA attention). Attention is the §96 `SPIKING-INCOMPATIBLE` faculty by design. ViT acceleration on AKD2000 would be the closest match — and AKD1000 *does not have it*. Even running anima as inference on AKD1000 requires either re-derivation to a CNN-like architecture or substantial structural surgery; it cannot accept the transformer block shape directly.

## §6 — anima implications (the §95 verdict re-verified + §97 mapping)

**§95 verdict CONFIRMED + TIGHTENED.** The on-chip-learning constraint (last-FC-only / binary weights / binary inputs) is more restrictive than the casual marketing reading suggests. AKD1000 cannot host anima's `§11-B-as-substrate` learning-channel experiment — the chip's learning channel is too narrow to count as "non-CE training-time emergence." `INFERENCE-ONLY-BLOCKED` stands.

**§97 coupling classification of an in-hand AKD1000:**

| Use | §97 cell | GOAL-relevance | Sustainability |
|---|---|---|---|
| Convert + deploy a *small frozen* anima-derived classifier → run inference on AKD1000 | (4) anima→actuator / pure-output display | DESIGN-OPEN, **GOAL-orthogonal** | HIGH (own hardware) |
| Real-chip validation of NEURO-MIRROR's LIF + event-driven dynamics (inference half) | inference-side mirror anchor | DESIGN-OPEN, **GOAL-orthogonal** | HIGH |
| Train anima on AKD1000 / decide §11-B-as-GPU-tautology on AKD1000 | NOT FEASIBLE | — | — (chip too narrow) |
| Host §108-scale (3B) or even §16-scale (283M) transformer | NOT FEASIBLE | — | — (1.2M neurons, no ViT, 8 MB SRAM) |

**Two honest scoped uses when the chip arrives:**
1. **NEURO-MIRROR inference anchor** — port the smallest LIF block from `neuro_mirror.py` (§117 mean Ψ-C1 0.611568) to MetaTF, run on AKD1000, confirm event-driven dynamics on physical async silicon match the mirror's prediction. Upgrades NEURO-MIRROR's `confronts()` contract from "mirror only" to "mirror + 1 real chip on the inference half." Genuine, modest, honest. Does NOT crack WALL-B's emergence/learning half.
2. **§97 (3) noise-as-SEED / (4) display** — AKD1000 + cheap MCU peripherals (see the Arduino auxiliary-gear discussion) could form the §97 (3)+(4) physical loop for the eventual deployed-anima inference instance — long-term, when an emergent anima exists.

Note: the chip that *could* decide `§11-B-as-substrate` (programmable plasticity, real local STDP-class on-chip learning) is **Loihi 2**, per §96. AKD1000 ≠ Loihi 2. AKD1000 ≠ AKD2000. The categorical disambiguation matters.
