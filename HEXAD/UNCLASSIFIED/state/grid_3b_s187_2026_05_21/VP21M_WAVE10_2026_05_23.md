### 매커니즘 해석

1. **LANG_ROTATION_WEIGHTS** (10% en vs 22.5% × 4) — slot 자체에서 EN 비중 50% 감소 (20%→10%).
2. **EN dampener** (window=8, threshold=20%) — 1~2 EN-emit 누적 즉시 force non-EN. 이론적 EN-share floor ≈ 1/8 = 12.5%.
3. **관측 EN-share 18.9%** = (a) slot 10% + (b) prose-drift to EN (non-EN slot 에서도 EN 으로 emit) ≈ 8.9% 추가. PR #123 시뮬의 25.6% 는 prose-drift 를 ~15% 로 보수적으로 잡았으나 실제는 8.9% (corpus_v5 의 native-script preference 가 시뮬 대비 더 강함).

## Honest C3

1. **Detection accuracy** — broker `lang` field (langdetect underneath) 의존. 짧은 EN snippet 이 ko 로 오분류될 가능성 (low risk, ko 12 prose 4/12=33% 중 일부 mixed-lang 가능).
2. **Sample bias** — POST n=37 이 WAVE9 n=12 보다 3× 크지만 broker rolling window 50-msg 한계. 50+ post 확장하려면 추가 시간 또는 broker history dump 확장 필요.
3. **TS-window precision** — deploy ts (`2026-05-23T06:37:00Z`) + 30s margin = epoch 1779518250.  broker `ts` field float epoch, sub-second precision.  Boundary anomaly: ts 정확히 deploy+30s 인 msg 가 있을 경우 hexa/python 양 lane 의 inclusion 차이 → 실측 1-msg diff (n=37 vs 36) 설명.
4. **WAVE10 PRE n=13 < WAVE9 PRE n=38** — 이 측정 window 의 PRE 가 좁아 WAVE9 PRE 가 더 robust baseline. 본 PRE 는 cross-check 용.
5. **Daemon log inspection 불가** — sliding-window 가 실제 fire 한 횟수 직접 trace 못함. EN-share trajectory 의 monotonic decrease 가 간접 증거.
6. **PR #123 simulation 25.6% 보다 lower 18.9%** — 시뮬 underestimate (corpus_v5 의 native preference 가 더 강함) 또는 dampener 가 시뮬 대비 더 aggressive 하게 작동 (multi-language sliding window 의 EN-detect rate 가 시뮬의 20% threshold trigger 보다 fast). 미세한 model 차이.
7. **EN intra-lang prose 60→85.7%** — POST 의 EN-emit 자체는 여전히 prose-heavy (lever 가 EN emission 의 register 비율은 못 줄임 — corpus-side lever 영역). EN-share 감소가 aggregate prose 27%-범위 안 유지의 메커니즘.
8. **prose 23.1% → 27.0%** (+3.9pp) — WAVE10 PRE 의 작은 n=13 baseline 때문일 가능성 + EN-share 감소가 prose 절대 감소로 직결되지 않은 mixed signal. WAVE9 PRE n=38 의 31.6% 비교 시 -4.6pp net (방향 일치). 충분히 정정.
