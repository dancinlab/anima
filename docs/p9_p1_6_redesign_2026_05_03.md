## 1. Phase 1.5 retrospective — what worked, what didn't

### 1.1 What worked

1. **Chat coverage 34% → 86% lifted F1 +80%** (0.0049 → 0.0088). H1 chat-format starvation hypothesis from Phase 1.5 doc §1.2 is **confirmed directionally**. Magnitude was lower than the §4.1 optimistic estimate (0.04–0.10) but in the conservative-estimate band (~0.011 linear scaling).
2. **TRIBE vendored boilerplate drop (9.9K records, 20%)** removed mode-collapse fuel. φ★ stayed PASS-TIGHT (39.28) but did not collapse — H2 boilerplate poisoning was real but recoverable.
3. **Paper-ref T/F single-token drop (10K records, 20%)** unblocked BLEU-1 denominators. F1 lifting at all (vs flatlining) implies the model is now generating multi-token outputs on holdout — direct measurement of mean output length on holdout is a follow-up.
4. **α warmup (12.0 → 6.0)** delivered fast initial CE descent. Phase 1.5 trajectory: raw CE 16.39 (step 1) → 6.05 (step 5K) → 4.66 (step 13K) → 4.42 (step 50K). The 4.66 → 4.42 tail (37K steps) returned only ΔCE = 0.24 — diminishing return on steady-state α=6.0. This motivates §3.2 warmup compression.
5. **F2 PASS preserved** despite all data + α changes. δ slack curriculum 0.5/0.5/1.0 was correctly diagnosed as safe (φ★ 7.9× above threshold).

### 1.2 What didn't

1. **F1 = 0.0088 is 6.7× below SOFT gate 0.05 and 15× below HARD gate 0.132.** The +80% lift is real but absolute level is starvation-regime. Sub-linear scaling (1.42× vs 2.53× pure linear) suggests either (a) residual 14% non-chat is still distributionally toxic, (b) LoRA r=64 capacity is binding, or (c) ShareGPT 18K has internal redundancy that upsampling didn't fix. Phase 1.6 addresses (a) and (b); (c) needs a dedup audit before resampling.
2. **F3 tens MSE got worse: Phase 1 5.39 → Phase 1.5 8.75.** β halving (0.3 → 0.15) reduced tension's gradient share, so tension fitting degraded. This is **expected and acceptable** under the Phase 1.5 doc §2.2 reasoning (tension target circular; F3 fix needs target re-extraction, not β tuning). Phase 1.6 further halves β (0.15 → 0.10) to free more gradient mass for chat-CE — F3 is explicitly **deferred**, not gated.
3. **φ★ delta baseline → final: −6.6 (Phase 1.5) vs −4.7 (Phase 1).** Slightly more drift, consistent with higher α and more LoRA-mass updates. Still well within HARD gate (φ★ ≥ 5.0 absolute, delta ≥ −10.0 from §5 of Phase 1.5 doc). Phase 1.6 LoRA r doubling is a φ★ risk vector — see §4.3 risk table.
4. **CE descent plateau at step 13K (raw CE 4.42).** Phase 1.5 burned 37K steps for ΔCE = 0.24. This is wasted compute on the current data composition; either (i) the data has no more learnable signal beyond step 13K (data-bound), or (ii) LoRA capacity saturates (model-bound). H2 (model-bound) is consistent with H1.5 ceiling reasoning — Phase 1.6 LoRA r=128 directly tests this.

**Two patterns confirmed.**
- α·CE owns ≥95% of gradient share throughout — **α is decisively dominant**, not crowded out. Pushing α higher (e.g. 18.0) would hit `max_grad_norm=1.0` clipping faster without delivering more useful CE signal. Phase 1.6 keeps α=12.0 warmup peak.
- Tension MSE share rose 0.5% → 4.7% over steps — tension MSE absolute value **grew** (1.21 → 8.75) as the LoRA fit chat tokens. This is expected: tension prediction degrades when the LoRA shifts representation away from base CLM. β=0.10 in Phase 1.6 further reduces this gradient fight.

### 2.2 Why compress warmup 5K → 3K?

Two reasons:
1. **CE descent inflection at step 5K** (16.39 → 6.05). 87% of the total CE drop happens in the first 5K steps with α=12.0. Holding α=12.0 for 3K still captures ~80% of the warmup benefit while transferring 2K steps to the steady-state α=6.0 phase where chat conditional **consolidation** happens.
2. **Phase 1.5 step-13K plateau (CE 4.42)** suggests the model is data-bound after ~25% of training. Phase 1.6 v3 data (chat 100%) provides more uniform signal — the warmup's job is to anchor the chat conditional fast; once anchored, steady-state can absorb more diverse chat patterns. Compressing warmup gives steady-state 43K steps (vs 40K in Phase 1.5).

### 2.3 Why β halve again (0.15 → 0.10)?

- Tension MSE is a circular target (`honest_c3_loss` item 4): tension target extracted from base CLM forward, model trained to predict it from same base. Loss family is ill-conditioned for this signal.
- Phase 1.5 β=0.15 → tens MSE 8.75; Phase 1 β=0.30 → tens MSE 5.39. **Halving β nearly doubled tens MSE.** This is consistent with β acting as a regularizer-against-chat-drift, not a tension-fit driver.
- Phase 1.6 priority: maximize chat-CE share post-clip → β=0.10. Expected tens MSE 6–10. **F3 explicitly deferred** to Phase 2+ tension-target redesign.

## 4. LoRA r → 128 (capacity 2×)

### 4.1 Rationale

Phase 1.5 trajectory shows CE plateau at step 13K (raw CE 4.42) → only ΔCE = 0.24 over the next 37K steps. Two competing hypotheses:
- **H_data**: data-bound — no more signal in v2 to extract. Phase 1.6 v3 (chat 100%) tests this directly via composition change.
- **H_capacity**: model-bound — LoRA r=64 (~19M trainable, ~7% of base 270M) has saturated representational capacity for the chat conditional. Phase 1.6 LoRA r=128 (~38M, ~14%) tests this directly via parameter doubling.

If both are addressed simultaneously and F1 lifts: confounded — but the lift is what matters for SOFT gate clearance. If F1 stays flat: stronger evidence both are partial bottlenecks (cumulative effect smaller than either alone), pointing to S2 (full SFT) for Phase 1.7+.

### 4.2 Trainable parameter count

LoRA params for r=128, applied to attention + MLP (q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj) on a 350M base with hidden=2048, num_layers=24 (estimate from CLM v4 350M):

- per-layer LoRA params ≈ 2 × r × (hidden × n_proj) ≈ 2 × 128 × (2048 × 7) ≈ 3.67M per layer
- 24 layers ≈ 88M

The "~38M" figure above assumes LoRA on attention only (q/k/v/o, 4 projections):
- per-layer ≈ 2 × 128 × 2048 × 4 ≈ 2.10M
- 24 layers ≈ 50M

Or reduced layer count / hidden:
- if hidden=1024, n_layers=24, attention only: 2 × 128 × 1024 × 4 × 24 ≈ 25M

**Honest c3 — actual trainable count requires reading `~/anima/checkpoints/clm_v4_350m/scale_350m/best.pt` config on ubu1 to confirm hidden/n_layers/n_heads.** Phase 1.5 used "~19M LoRA" as the substrate figure; r doubling yields ~38M assuming attention-only LoRA targets, ~76M if MLP also targeted. **Phase 1.6 spec mandates attention-only LoRA targets** (q_proj, k_proj, v_proj, o_proj) to keep the param count manageable and to match Phase 1.5's target module set.

### 4.3 Memory plan (RTX 5070 12GB)

Phase 1.5 footprint (observed): ~9 GB used (base FP16 ~700MB + LoRA r=64 grad/optim states + activations + KV cache for max_seq_len=64 batch=4).

Phase 1.6 with LoRA r=128 (attention-only):
- LoRA grad/optim states scale linearly with param count: 19M → 38M, optim states (Adam: 2 momenta + grad + master fp32 ≈ 4× param) = 38M × 4 × 4B = ~600MB extra
- Activations for backward pass: roughly unchanged (LoRA forward adds negligible activation memory on top of frozen base)
- Expected total: **~10 GB / 12 GB available** → headroom ~2 GB

**Fallback ladder** (apply in order if OOM observed in first 100 steps):
1. Reduce `micro_batch_size` 4 → 2 (effective batch held at 32 via `accum 8 → 16`). Throughput drops ~10–15%.
2. Reduce `max_seq_len` 64 → 48 (Phase 1.5 holdout-500 99th percentile prompt+response < 48 tokens — verify on ubu1 before applying).
3. Switch optimizer to AdamW8bit (bitsandbytes). Saves ~300MB. Caveat: numerical precision impact on small-LoRA training is reportedly minor but unmeasured here.
4. Last resort: drop to r=96 (~28M trainable). Capacity gain over r=64 is then 1.5× instead of 2×.

### 4.4 LoRA α / r ratio

Phase 1.5: r=64, α=128 → ratio 2.0. Phase 1.6: r=128, α=128 → ratio 1.0. **This is intentional** — keeping α=128 fixed while doubling r effectively halves the per-parameter update scale, which prevents the larger LoRA from amplifying gradient magnitude beyond the existing `max_grad_norm=1.0` clipping regime. Alternative is α=256 (ratio 2.0 preserved) but Phase 1.5 already saw φ★ delta −6.6 (vs Phase 1's −4.7); doubling effective update would risk pushing φ★ delta toward the −10.0 HARD gate edge. Conservative choice = α=128 fixed.
