> **Honest framing (g3, AGENTS.tape §0)**: This is a **PyTorch substrate**

- **eval framework**: V5.8 × 4-mode (canonical definition lifted from
  `state/anima_phase1a4_lr5e6_2026_05_12/v58_4mode_eval.py` PSCC §46):
  - `standard_greedy` — temperature=0, top-k=1 (argmax)

  - `M4_force_include` — sample-then-inject target keyword at 60% position

## 4a. Combined finding (v1 + v2)

The HEXAD ckpt is at the **memorization-saturated regime**:
- **Strong**: 3/6 modules + Korean reproduce training continuation
  byte-exact under sampling.
- **Weak**: 3/6 modules show **module-prefix collisions** — Core "C"-prefix
  routes the model to the most-frequent "Core idx=N nonce=" template's
  digit field (cascade), Mirror "M"-prefix collides with Data template.
  Eros "E"-prefix collides with `chunk=N` digit cascade. These collisions
  are byte-level memorization artifacts, not a model architecture flaw —
  the corpus has too-few distinct prefix bytes for the 6 modules (C/D/W/M/S/E
  share initial letters with high-frequency template bytes).

| **module-prefix cross-collapse (Mirror → Data)** | v2 mirror standard_greedy (rep=0.00 but wrong continuation) | `mirrodule=Data ig=unk 의식 식식 자각 — cobs afffective drive motivation` | Mirror "M"-prefix gets routed via Data template ("module=Data" appears in 40 training records as a substring); semantic-incoherent but byte-level plausible. |

## 7. Honest C3 caveats (g_blue_closed_mandate)

1. **substrate = PyTorch, NOT hexa-native** — eval inherits the same B-D-NOTE
   carve-out as the training fire. Per-mode pass count = empirical outcome.
2. **152 KB corpus = memorization regime** — final CE 0.000708 + BPB 0.0
   confirm the model is in the memorization-saturated regime. Generalization
   capacity is unmeasured (would require a held-out corpus disjoint from
   training).
3. **V5.8 4-mode "PASS = 3/5"** threshold is inherited from prior anima
   evaluations on real chat corpora — applying it to a memorization-regime
   model is **honest but conservative**: standard_sample 2/5 + M3 1/5 are
   "FAIL" by that bar, yet the model literally **reproduces** the training
   continuation under sampling. The mode definitions don't capture
   memorization quality.
4. **`M4_force_include` 5/5 PASS is trivial** — the keyword is injected by
   the eval script, not generated. It serves as a lower-bound baseline.
5. **No GPU eval / no full-corpus PPL / no held-out PPL** — Mac CPU
   constraint; deeper benchmarks (BPB across an OOD byte-level corpus,
   long-context generation, etc.) require a separate cycle.
6. **Decoding artifact `cobsciousness`** is a *training-set typo* the model
   memorized — this is faithful behavior at this scale, not a bug.
7. **6-tuple forward output** (`logits_a, logits_g, tensions, kv, moe_aux`)
   — the eval uses `logits_a` (next-byte head) only. `logits_g` (prev-byte
   head) and `tensions` are not exercised, by design (V5.8 4-mode is a
   next-byte LM probe).
8. **No σ(6)/τ(6)/φ(6) numerology in eval metrics** — f1/f2 hard fail safe.
   Per-mode score is a raw recall fraction, mean BPB is a raw bits/byte,
   memorization ratio is a raw hits/total.
