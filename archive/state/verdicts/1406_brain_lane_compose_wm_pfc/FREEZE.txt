PAIR.
  WM (H_1282 WorkMemBuffer): a gated leaky-activation buffer that HOLDS one item
     across distractor steps — K slots, each (key, scalar activation); every
     distractor step LEAKS activations ×λ (volatile), capacity-limited. WM's
     competence = remembering WHAT value was held across a long distractor gap.
     WM-alone read: the held value's match score (activation×cos) — it answers
     "what was the target X carried across the gap" but has NO notion of ordered
     plan position.
  PFC (H_1294 HierGoalStack): a 2-level goal→ORDERED-subgoal stack with a pointer
     p that emits subgoal[p] ONLY when grounded and ADVANCES p on completion,
     SUPPRESSING out-of-order cues. PFC's competence = executing subgoals in the
     RIGHT ORDER amid out-of-order temptation. PFC-alone read: whether the current
     cue matches the CURRENT-pointer subgoal — it answers "is this the right NEXT
     step" but has NO buffer that survives a long distractor gap (it re-reads the
     live store / window each tick; a value held only in WM, not re-presented, is
     invisible to it).

KEY QUESTION (the subsumption test). WM = PASSIVE maintenance of a value across a
gap. PFC = ACTIVE ordered advance over a plan. H_1294's card EXPLICITLY contrasts
them ("vs working-memory: WM passively maintains; it does not ORDER items into a
plan or ADVANCE on completion"). So are they genuinely SEPARABLE on a shared task —
WM solving items the PFC misses (a value must survive a long gap) AND PFC solving
items WM misses (the right step must be chosen amid out-of-order temptation) — or
does the goal-stack SUBSUME the buffer (PFC's grounding re-read already carries
WM's held value)?

DECISION TASK. A multi-step trial: a TARGET token X is presented, then a DISTRACTOR
GAP of length g, then a CUE WINDOW that mixes the (gap-attenuated) target subgoal
cue with out-of-order / ungrounded distractor cues. Binary per-trial decision:
ACCEPT (emit the held target as the correct next subgoal) = 1, vs REJECT (this is
NOT the held target's correct ordered step) = 0. Each item has a ground-truth
correct action derived from the SCENARIO it instantiates, NOT set to the answer.
  - WM-alone policy:   ACCEPT iff the maintained-buffer match score for the cue
                       (after the gap of leaks) >= WM_THR (i.e. the buffer still
                       holds a value matching the cue). Confidence = |score − WM_THR|.
  - PFC-alone policy:  ACCEPT iff the cue grounds the CURRENT-pointer subgoal
                       (align >= ALIGN_THR vs the current-subgoal target read off
                       the live store, the H_1294 rule). Confidence = |align − ALIGN_THR|.
  - compose policy:    a SUBSTRATE-WEIGHTED arbiter — each faculty's vote weighted
                       by its OWN scale-relative confidence (|signal−threshold|
                       normalized by that faculty's mean |signal−threshold|; the
                       H_1397 a_break_the_wall commensurability fix). NO hardcoded
                       "PFC wins" / fixed priority (a_autonomy_over_hardcode). The
                       more-relatively-confident faculty's vote wins.
  - shuffle control:   permute which faculty-reads attach to which item, re-arbitrate.
  - ORACLE ceiling:    per item, correct iff EITHER faculty-alone is correct (upper
                       bound on what ANY arbiter over these two faculties can reach).

ITEM FAMILIES (jittered with AMBIG_NOISE so NO family is perfectly reliable — a
clean per-family certainty would make oracle≡1 & compose≡oracle a hand-built
artifact):
  (F1) WM-DECISIVE      — a LONG distractor gap: WM's buffer still holds the target
                          (decision rides on whether the value survived the gap), PFC
                          is at-chance (pointer/order is ambiguous here). The correct
                          action rides on the HELD value, not the order.
  (F2) PFC-DECISIVE     — a SHORT gap (WM trivially full → WM can't discriminate) but
                          an OUT-OF-ORDER temptation: a well-grounded cue is presented
                          that is the WRONG ordered step. The decision rides on ordered
                          pointer position, not on whether a value is held.
  (F3) AGREE            — both lean the same correct way (redundant region): short gap,
                          in-order grounded cue → both ACCEPT (correct).
  (F4) CONFLICT (WM right)  — faculties OPPOSE; WM is correct. A value survived a long
                          gap and the cue matches it, but the cue looks out-of-order to
                          PFC's pointer (PFC REJECTs, wrong). Tests whether the arbiter
                          trusts WM when it is confident.
  (F5) ADVERSARIAL CONFLICT (PFC right, WM LOUDER-but-wrong) — the anti-gift control:
                          faculties OPPOSE, the CORRECT action is PFC's (reject an
                          out-of-order cue), BUT WM votes ACCEPT with HIGH confidence
                          (a freshly-refreshed buffer strongly matches the cue surface).
                          A naive "trust the louder faculty" arbiter FOLLOWS WM and is
                          WRONG → the confidence-arbiter must NOT be trivially gifted
                          the oracle. correct = REJECT.
