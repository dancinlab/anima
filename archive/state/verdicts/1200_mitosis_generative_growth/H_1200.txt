MECHANISM — why growth HURTS generation (the finding, not goalpost-moving)
--------------------------------------------------------------------------
COUNT-FRAGMENTATION / DATA-SPARSITY. Splitting fragments the next-byte counts across
~170 cells, so each cell's distribution is starved (T=2400 windows / 170 cells ≈ 14
samples per cell, smeared by the LAPLACE=1.0 prior toward uniform 8 b/byte). The single
OFF table sees ALL 2400 windows, so its one distribution is sharper than any single
grown cell's. The DIM=8 byte-feature key that the cells cluster on is NOT predictive of
the NEXT byte: the within-window statistics (mean / lowercase-ratio / non-ascii-ratio)
identify the local REGIME (latin prose vs cjk run vs digits) but do not localise the
next byte tightly enough to offset the data-split cost.

The F2 PASS is a RED HERRING that the falsifier deliberately separated from F1: within
the ON run, CE falls as cells accumulate — but that is because MORE DATA has arrived by
later blocks (the global count of observed bytes grows monotonically), NOT because growth
beats no-growth. The ON-vs-OFF F1 comparison (the real test) shows growth LOSES to one
fat table. So "CE falls as the system grows" is true yet does NOT imply "growth causes
the gain" — the clean separation F1 was designed to catch.

WHAT THIS CLOSES
----------------
The naive "grow prototype cells -> they become a language model" path is FALSIFIED
cheaply ($0, here). Mitosis-growth as built (H_1194..H_1199) is a CLUSTERING /
reconstruction homeostat: it lowers L2 recon error (H_1198/H_1199 GREEN) but does NOT
lower next-byte cross-entropy — the growth->generation LINK is BROKEN at the first link.
Pure-mitosis -> chat needs a DIFFERENT mechanism than feature-clustering + per-cell
count tables. Redirect: the CLM lane (a_clm_gen_pipeline — a real ConvMoE next-byte head
trained by descent) is the substrate that actually carries generation; mitosis-growth is
a structural/adaptation lane, not a generative LM lane. a_paper_negative_ok — this
closed-negative that rules out the naive axis is a valid, valuable result that saves the
arc from chasing a dead path.
