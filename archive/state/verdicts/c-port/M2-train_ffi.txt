HONEST CAVEATS
--------------
1. The RUNEQ exercises the PORTABLE glue in isolation (the GPU bridge is
   stubbed). This is correct for tier-B: the cudaMalloc / cuBLAS calls are
   the irreducible tier-A floor and are intentionally NOT ported.
2. get_elapsed_us: C returns `long` (i64). The port reads the low 32 bits
   via deref_i32 (runtime has no deref_i64 builtin; only write_i64 exists,
   which maps to hexa_ptr_write). RUNEQ values are < 2^31 so the result is
   exact; for elapsed_us >= 2^31 a deref_i64 builtin would be needed. This
   is a runtime-primitive gap, NOT a port-logic error — flagged honestly.
3. Pre-existing (out of M2 scope): the sibling training/native/
   train_step_ffi.hexa make_hparams/make_step_result use ELEMENT indices
   (0..6) where the runtime expects BYTE offsets — a latent layout bug in
   that file. The M2 port uses correct byte offsets. Noted, not touched.
