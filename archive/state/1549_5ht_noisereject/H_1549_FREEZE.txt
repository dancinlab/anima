THE MEASUREMENT (NEW, distinct from H_1548's correctness axis):
slow-store PRECISION = of the bindings the sweep COMMITTED to the permanent slow store, what
fraction are REAL (a CONFIRMED or CONTRADICTED key, which has a ground truth) vs NOISE (a
singleton key with NO truth). A store that commits noise bindings is permanently polluted;
PRECISION measures that pollution directly (committing noise LOWERS precision). This is NOT
correctness (does the value match) — it is INTEGRITY (should this binding be in the permanent
store AT ALL). recall-recovery cannot fix a polluted permanent store.

  precision = (# committed keys that are REAL) / (# committed keys total)
  REAL key  = CONFIRMED or CONTRADICTED (has a ground-truth binding)
  NOISE key = singleton, written once, never reconfirmed, NO truth

DISTINCT vs H_1548 CORRECTNESS: H_1548 asked "is the committed VALUE right" (recency fixes it).
H_1549 asks "should this binding be committed AT ALL" — a singleton noise key has no right
value; the only correct action is to NOT commit it. Recency CANNOT decide this (a noise key has
a last_val too), confirmation-count CAN.

CONTRADICTION/NOISE stream (REUSES H_1532 MemStore / key_vec / FNV-1a / suppress_retrieval
