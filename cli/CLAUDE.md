# cli/ — anima CLI entrypoints

**Purpose:** the collection of anima entrypoints. Inference/eval entry (`anima.hexa`, with evaluate·serialize·train as subcommands) + the production trainer (`train.hexa`). Among the py entrypoints, `anima.py` is retired (`retired 2026-06-28`); **`train.py`·`evaluate.py` remain the canonical py train/measure entrypoints** (`anima train --py`·`anima evaluate --py`) — since the hexa trainer is mid GPU-util fix, py is the currently-working train path. Scoped augmentation of the root `CLAUDE.md` — on conflict, root wins.

## Rules

> **ρ-AXON reach panel** (`cli/rho_axon.py`, opt-in `anima evaluate --py <clm> --rho-axon`) = the from-scratch owner redesign of the G0-G6 ladder. Mapping — CARRY `ρ·form`←G0 coherence · `ρ·store`←(new) · BRANCH `ρ·weave`←G1 recombination-WALL · `ρ·leap`←G2 novelty · `ρ·fan`←G6 ideation · COUPLE `ρ·tether`←G5 non-fabrication · `ρ·self`←G3 identity. HILLOCK validity-gate + `ρ·form`/`ρ·fan`/`ρ·leap` are live; `ρ·store`/`ρ·weave`/`ρ·tether`/`ρ·self` = PENDING (their frozen probe sets are a follow-on). Signal = collapse-Δ vs ≥2 controls, never a raw value (FORM tunable · BIND earned · p7). **G0-G6 stays the documented DEFAULT eval panel; `--rho-axon` is the opt-in ρ panel.**

- **`anima evaluate <ckpt>` = the canonical reach-eval single entry (`a_engine_native_learning`)** — generator L3 mouth (`gen_auto_ideate`) → engine-native scoring on the G0-G6 panel (the default; the ρ-AXON reach panel is opt-in via `--rho-axon`, see the note above). The subcommand is `evaluate` (code `argv[0]=="evaluate"`), not `eval`. No per-gate python harness·ad-hoc decode bypass.
- **`anima evaluate --py <ckpt>` = the py 2-production measurement path (`a_engine_native_learning` 2-production)** — with the `--py` flag the launcher scores G0-G6 via **`cli/evaluate.py`** (torch-free numpy `g_eval_all`) instead of hexa det-eval (`cli/evaluate.hexa`, OWN-GEMM fp64). Same frozen bars·byte-parity, so **equal terminal eligibility** (not a 2nd-class mirror). Use = when a big ckpt (303M+) OOM-dies under hexa bump-allocator fp64 det-eval (numpy frees memory per decode → robust for measurement-heavy full eval). The launcher consumes (strips) `--py` so `evaluate.py` receives only `<ckpt> [--corpus …] [--gen N]`. Both anima.hexa/anima.py launchers lockstep.
- **`anima train --py` = the canonical py train path (`a_clm_gen_pipeline` Lane-P bridge)** — with the `--py` flag the launcher (`anima_train_mode`) trains GPU-bound via **`cli/train.py`** (torch Lane-P CLMConvMoE + SAVANT/MITOSIS + `--arm`×`--objective` compositional lever) then serializes `.clm`, instead of hexa `cli/train.hexa`. Symmetric implementation with `anima evaluate --py` (`--py` consume·`cd $ANIMA_SRC`·second-exec cat of the result-file; train streams to stdout so a shell `> rf 2>&1` redirect avoids long-run pipe-close). torch-side is **DIRECTIONAL** — the verdict holds only via engine-native re-measurement of the serialized `.clm` with `anima evaluate --py` (`a_engine_native_learning`). PULL the ckpt before teardown (`a_fire_recover_complete`). `anima train` without `--py` dispatches to `cli/train.hexa`.
- **`anima sweep` = the canonical multi-GPU lever-sweep orchestrator (single-entry, replaces scratch `fire_*.sh`)** — round-robin-pins each (arm,objective) cell of the `--arms a,b`×`--objectives o1,o2,…` matrix onto `--gpus 0,1,2,3` (max-concurrent = GPU count; a cell waits for a free GPU). Per cell: ① `CUDA_VISIBLE_DEVICES=<gpu> python3 cli/train.py …` (303M `.clm` train) → ② if `--measure`, `CUDA_VISIBLE_DEVICES="" python3 cli/evaluate.py <clm> --corpus … --gen N` (CPU numpy G0-G6 / ρ-AXON reach) → ③ per-cell done flag. After all cells finish, it parses each `<tag>.meas.log` and aggregates the (tag|G0|G1 bd/ms|G2 novel|G6 dist/fals|closure|status) table to the console + `<out-dir>/SWEEP_SUMMARY.md`. Flags **G1-PASS candidates** (best_distinct≥2 ∧ >max_single) and **overfit-collapse INVALID** (G0 FAIL + train CE→0 collapse = measurement void, corpus starvation). `constructive_bind` auto-drops `--bf16`→fp32 due to the missing torch.fft bf16 kernel (H_1823); the rest keep bf16. **The orchestrator calls the canonical engines (train.py/evaluate.py) only as subprocesses** (itself torch-free, no import = single-entry discipline) — isomorphic to the `anima_train_mode`/`anima_evaluate_mode` shell-out pattern. sweep is inherently py (it orchestrates the py trainer/evaluator), so it always dispatches to `cli/sweep.py`, no hexa branch·no `--py` flag. **verdict discipline**: the per-cell `.clm` engine-native measurement is terminal, train-side CE is DIRECTIONAL (`a_engine_native_learning`) — even a G1-PASS candidate cements only from verbatim measurement output (no tune-to-green).
- **`anima corpus <format>` = the canonical train-corpus generation single entry (implemented · owner directive: henceforth corpora go through this only)** — anima's first `ρ·weave` (recombination · former G1) engine-native lift is not on the objective/readout/coverage axis but the **data-format axis** (derivation-trace: rewriting the target into a `DEF/RULE/OUT` derivation makes echo=composition, so the CE=echo meta-law no longer applies — H_9124 DERIV G1 PASS ∧ FLAT control FAIL). `anima corpus derivtrace|flat …` (`--held-out I,J`·`--seed`·`--concepts FILE.json`; with the same seed, derivtrace/flat are a content-matched 2-arm control) → `anima_corpus_mode`→`cli/corpus.py`. **All anima train-corpus generation is forced through this single entry** ★scope: `anima corpus` = **procedural/synthetic corpus generation only** (research-lever·rule generation like derivtrace) — the actual **chat train corpus is NOT this**. chat trains from real natural-language data (`a_chat_registers` 4 cells 🇰🇷·🇬🇧×general·SNS = web/wiki/conversational + Instagram/YouTube SNS) **curated·downloaded as HF datasets** (the `sidecar dataset` registry + `a_chat_registers`) via `anima train --corpus <4-cell>`. I.e. 'generation (procedural) = anima corpus' ⊥ 'real-data curation = HF/sidecar dataset' — do not make the latter with anima corpus (rule-generating external natural language violates p1-p8). — do not scatter raw `gen_*.py`·ad-hoc scripts into state/·summer (the corpus-reproduction SSOT = `cli/corpus.py`). Pure procedural string, so no torch/`claude -p`/external LLM (p1-p8: substrate-native, keep external-LLM bias out of the training data). Default concepts=g6_ideation cz[] (frozen G1 gate-aligned, held-out generalization memorization-free). Regardless of the robustness-fire (H_9124 multi held-out+G2+paraphrase) outcome, **the corpus-generation tool itself is canonical** — add new formats as subcommands in this file too.
- **Entry only via the installed canonical `anima` PATH command (`hx install anima`)** — directly running `hexa run cli/anima.hexa`·`python cli/*.py`·an engine-internal scorer is blocked by the `.harness/enforcement.json` H-ANIMA-SINGLE-ENTRY pre_bash (#2603). But `verify_clm_v2.py descent`·`serialize_standalone.py`, which the hexa canonical path calls as internal subprocesses, are fine (pre_bash hooks only the agent top-level, not internal shell-outs).
- A ckpt verdict holds only via `.clm` → `anima evaluate` engine-native re-measurement — no standalone verdict from torch-side probe scoring (a research mirror = DIRECTIONAL).
- `train.hexa`'s numeric kernels (forward/CE/decode-logits) are verified by per-component byte-match against a numpy `math.log` + torch fp32 golden reference (CI fixture). A device to catch `dt_ln` divergence·own-GEMM TF32 decode divergence (reference-match, not a py-engine mirror).
- The post-serialize HELD-OUT DESCENT gate is mandatory (`verify_clm_v2.py descent <clm> <heldout>`) — `a_clm_gen_pipeline`. `verify_clm_v2.py` (torch-free numpy mirror) is not retired = the canonical descent tool that train.hexa shell-outs at runtime.

## Gotchas

- **`--gen 0` is NOT "unlimited" (evaluate.hexa `g_eval_all`):** inside `g_eval_all`, `if gen > 0 { gen } else { _g_default_gen() }` → 0 collapses to 40. The G1 budgets (single=80, composed=120) also use the ref value as-is when `gen<=0`. If you mean "wide", specify `--gen 80` or more.
- **Engine CE (`clm_forward_ce`) masks overfit as GREEN due to the `dt_ln` bug** → cross-check `.clm` quality with the numpy mirror (`verify_clm_v2.py`, `math.log`). Until `dt_ln` is fixed, a standalone engine-CE verdict is DIRECTIONAL.
- **train-loss/lossF≈0 = memorization, not capability** — without a held-out CE you can misjudge, like clm303, a 4MB single-cell 120× repeat memorization as 'train success'.
- `eval_pod.sh` requires hexa ≥ v0.311.0 (earlier versions = 85GB OOM from a farr leak).
- **serialize backend unification:** the `anima serialize` backend = the unified `core/serialize.py` (parallel to `core/decode.hexa`'s unified CONV+BYTE decoder) — a byte-faithful 1:1 merge of CONV `.clm` (`serialize_v3` = the byte-grammar SSOT, golden `reexport_d768_v2_fast.clm`) + ByteGPT `.bin` (`serialize` = the `.pt`→`.bin` bridge). Live cli/ importers (`cli/train.py` `import serialize as S`+`as BGS` · `cli/serialize.py` · `serialize_standalone.py`) resolve `serialize` from `core/`. The old `clm_serialize_v2.py` stays as the historical backend (still imported by archive/state trainers + `verify_clm_v2` self-tests); `bytegpt_serialize.py` moved to `archive/tool/` (0 live importers). serialize is irreducibly Python (must unpickle a torch `.pt` — `a_engine_native_learning`: train/serialize may use torch).
