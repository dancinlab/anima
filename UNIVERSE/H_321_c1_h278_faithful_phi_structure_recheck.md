## 3. Method (방법 — 결정적 · hexa-only · llm:none · $0)

엔진은 **재발명하지 않는다**. 기존 stdlib + HEXAD/IIT4 lib 재사용:

- `stdlib/consciousness/iit4_relation.hexa` — `phi_structure(tpm, n, sys_state)
  -> [nd, sum_d, nr, sum_r, total]`. M3 엔진: distinction 수집(MICE φ_d > 0) +
  2nd-order congruent-overlap relation 결합.
- `HEXAD/IIT4/lib/iit4_eca.hexa` — `eca_tpm(rule, n)`: Wolfram rule → 주기적
  ring 의 state-by-node TPM. H_278 의 동일 ECA 규칙군 (rule {30, 110, 90, 54,
  110, 110}) 을 그대로 적용.

**구조 노름 측정**:
각 (rule, n) 쌍에 대해:

> total(rule, n, sys_state) = Σφ_d + Σφ_r  ← phi_structure[4]

전체 시스템 `sys_state` 는 nesting 두 크기에서 **결정적 비-자명 혼합 패턴** 으로
고정 (n=4 → sys=11 = 0b1011, n=5 → sys=21 = 0b10101). 외부 단위 배경-조건화는
phi_structure 가 full system 위에서 작동하므로 불필요.

**Nesting pair 정의**:
H_278 의 패널 6 스케일은 모두 같은 ECA 규칙군이므로, "nesting" 은 substrate 의
**ring 크기 n=4 (4 cells) → n=5 (5 cells)** 확장으로 정의 — 같은 규칙·같은
초기-패턴-규칙(`i%3 != 0` 같은 H_002/H_278 의 deterministic init은 phi_structure
가 sys_state 만 받으므로 sys_state 의 비트 패턴 형태로 인코딩). 이는 H_278 의
"n=8 lattice 안에서 6 스케일을 비교" 와 다른 nesting 축이지만 — **C1 이 묻는 본
질문 ("Φ-구조가 substrate 크기 변화에 대해 어떻게 행동하나")** 에 정확히
대응한다.
