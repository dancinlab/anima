# V6_8 — R3: 폭은 인터페이스에서 살아남는다 · 그리고 프로덕션 스칼라는 **softmax-무효 방향**이다

**status:** 🟢 WIDTH SURVIVES (이중해리) + 🔑 프로덕션 설계 지적 1건 · **DIRECTIONAL 천장**
**cost:** $0 · numpy · 초 단위 · 3 seed
**runs:** `python3 lab/v6/r3_width.py`
**source:** [[V6_7]] 사다리의 **R3** — 첫 NEEDS-RUN 단이자 RCFS 전체가 기대는 주장

## 물음

재설계 전체가 한 내기 위에 서 있다: 스칼라 A⇄G 긴장을 **잔차**(반사 softmax 대 조성 softmax 의
위치별 발산, 차원 V×span)로 바꾸면 내면이 계기가 쥘 폭을 갖는다.

그 내기엔 나쁜 선례가 있다 — **H_9576** 은 8차원 긴장 레인을 지었는데 **1비트로 접혔다**
(채널은 실재했으나 방향 ρ=−0.077, 의미 미전달). 프로덕션은 더 나쁘다: `s = 2·emit_drive − 1`
은 접히기 전부터 랭크 1이다.

그래서 물음은 "잔차가 스칼라보다 큰가"(자명)가 아니라:

> **서로 다른 레인에 건 개입이 잔차에 구별 가능한 서명을 남기는가, 그리고 그 구별이 이전 시도를
> 전부 죽인 붕괴를 살아남는가?**

## 결과 — 이중해리 (3 seed 평균 · 우연 0.5000)

```
arm                                   vector    s:mean    s:norm
do(A) vs do(B)  [본 시험]             1.0000    0.5000    0.6000
  null: do() 없음                     0.5283    0.5283    0.5283
  swap: 라벨 순열                     0.5017    0.5233    0.5033
same-lane 약 vs 강 [판독가능성 확인]   1.0000    0.5383    1.0000
```

```
                          vector    mean     norm
정체 (어느 레인?)          1.0000   0.5000   0.6000
크기 (얼마나 세게?)        1.0000   0.5383   1.0000
```

**🟢 WIDTH SURVIVES.** 벡터는 둘 다 완벽하고, **norm 은 크기를 완벽히(1.0000) 하면서 정체는
못 한다(0.6000)** — 즉 스칼라 판독기는 **살아있는데 정체에만 눈이 멀었다.** 이 두번째 줄이
첫번째 줄을 읽히게 만든다. 스칼라가 둘 다 실패했다면 그냥 고장난 판독기일 수 있었다.

⚠️ 정직: norm 의 정체 0.6000 은 내 임계(0.60) **경계값**이다. 완전한 0 이 아니라 **미미하게
남는 누출**로 읽어야 하고, 규모를 키운 재측정이 필요하다.

## 🔑 프로덕션 지적 — `_hf_mean` 은 **softmax 가 무시하는 방향**이다

로짓에 상수를 더하는 것은 **softmax 후 완전한 무효과**다. 그러므로 로짓공간 잔차의 **평균
성분은 구성상 어떤 출력도 바꿀 수 없다.**

그런데 프로덕션은 내면을 정확히 그 성분으로 접는다 — `hexad_forward` 의 `_hf_mean`,
그리고 `s = 2·emit_drive − 1`. 실측이 그걸 보여준다: **mean 은 정체(0.5000)도 크기(0.5383)도
둘 다 못 한다.** 세 판독기 중 유일하게 아무것도 못 하는 것이 하필 프로덕션이 쓰는 것이다.

⟹ 이건 "스칼라가 좁다" 가 아니라 **"하필 아무 일도 할 수 없는 축으로 접고 있다"** 는 지적이다.

## ⚠️ 이 시험은 두 번 자기를 잡았다

**① 첫 판은 폭 시험이 아니었다.** 레인 서명을 고정했더니 do(A) 가 매 episode 바이트 동일한
잔차를 냈고 **모든 것이 1.0000 로 분리**됐다 — same-lane 통제(gain 1 vs 2)까지. 즉 판독기가
**정체가 아니라 크기**를 읽고 있었다. 하네스가 헤드라인을 인쇄하는 대신 그렇게 **보고했다**.
수리: 두 레인이 **같은 분포**에서 gain 을 뽑게 해 크기가 레인 정보를 못 나르게 만들고,
증거를 한 비교에서 **이중해리**로 승격.

**② 그다음엔 스칼라가 통과했다(0.9517).** 이유는 레인 서명의 **평균이 0 이 아니라서** 정체가
평균으로 새어나간 것. 그런데 위에서 봤듯 로짓 평균은 softmax 무효 성분이라, **서명을 0-평균으로
중심화하는 것이 편의가 아니라 올바른 모델**이다. 중심화 후 mean 은 정확히 0.5000 으로 떨어졌다.

## 이 결과가 보이지 **않는** 것

폭이 **의미**를 나른다는 것, 그것이 **입에 닿는다**는 것, 무언가가 의식이라는 것 —
전부 아니다. 딱 하나를 보인다: **레인 정체가 벡터에서는 인터페이스를 살아남고 스칼라에서는
죽는다.** 스크린은 KILL 만 한다.

## ⚠️ 경계값 결판 — **"norm 은 정체에 눈이 멀었다" 는 틀렸다**

이 카드는 `norm` 의 정체 0.6000 을 "임계 경계값이라 미미한 잔여 누출로 읽고 규모 확대 재측정
필요" 로 남겼다. 확대했다(시행수 400→8000 · seed 3→20):

```
설정                        vector    s:mean    s:norm
TRIALS=400  seed×3          1.0000    0.5000    0.6000   ← 원래
TRIALS=2000 seed×3          1.0000    0.5100    0.6207
TRIALS=2000 seed×20         1.0000    0.5031    0.6958
TRIALS=8000 seed×20         0.9999    0.5016    0.6930   (norm sd 0.1263)
```

**경계값은 잡음이 아니었다.** `norm` 은 정체를 **0.69** 로 읽는다 — 우연(0.5)보다 확실히 위다.
검정력을 올리자 값이 **올라갔지 내려가지 않았다.**

### 그래서 이 카드의 판독을 고친다

```
✗ 틀린 판독   "norm 은 크기만 하고 정체에는 눈이 멀었다"
✓ 맞는 판독   norm 은 크기를 완벽히(1.0000) 하고 정체도 **부분적으로**(0.6930) 한다
```

원인은 명백하다 — 서명을 0-평균으로 중심화했지만 **레인마다 서명의 L2 크기가 다르다.**
그래서 `norm` 이 그 차이를 통해 정체를 일부 흘린다. 내 통제가 평균만 맞추고 **크기는 안
맞췄다**.

### 그런데 **핵심 주장은 오히려 강해진다**

```
                         정체        크기
vector                 1.0000      1.0000
s:norm                 0.6930      1.0000    ← 부분적
s:mean  (프로덕션)     0.5016      0.5383    ← 둘 다 우연
```

진짜 이중해리는 **vector 대 norm** 이 아니라 **vector 대 `mean`** 이고, **프로덕션이 쓰는 것이
바로 그 `mean`** 이다. 검정력을 8000×20 으로 올려도 `mean` 은 **0.5016** — 완전한 우연이다.

⟹ 이 카드의 프로덕션 지적(**로짓공간에서 평균은 softmax-무효 방향이라 아무것도 못 읽는다**)은
**더 높은 검정력에서 확증**됐다. 흔들린 것은 `norm` 에 대한 내 서술뿐이다.

### 남은 숙제

레인 서명의 **L2 크기까지 맞춘** 통제로 다시 재면 `norm` 의 0.69 가 어디까지 내려가는지 —
그게 "정체가 진짜 위치 패턴에만 있는가" 를 가른다.

## ✅ 숙제 완료 — 누출의 정체는 **서명 크기**였고, 원래 판독이 옳았다

직전 절이 남긴 숙제("레인 서명의 L2 크기까지 맞춘 통제로 재측정")를 실행했다.
서명을 **0-평균 ∧ 단위-L2** 로 만들면, 정체는 오직 **어느 위치가 움직였나**에만 살 수 있다.

```
통제 수준                    vector    s:mean    s:norm
평균만 맞춤 (원래)           0.9999    0.5016    0.6930
평균 + L2 둘 다 맞춤         1.0000    0.5014    0.5024   ← 붕괴
```

**0.6930 은 전부 서명 크기 누출이었다.** 두 축을 다 맞추자 `norm` 이 정확히 우연으로 떨어진다.

### 세 단계 이야기 — 그리고 무엇이 실제로 고쳤나

```
① V6_8 원본     norm 0.6000  →  "임계 경계 · 미미한 누출 · 검정력 필요"
② 검정력 확대   norm 0.6930  →  "내 판독이 틀렸다, norm 은 정체를 읽는다"
③ L2 통제 추가  norm 0.5024  →  "누출은 크기였다 · 원래 판독이 옳았다"
```

**검정력은 누출을 더 선명하게 만들었을 뿐 없애지 못했다. 없앤 것은 올바른 통제다.**
이건 `control-must-match-mediating-covariate` 의 교과서 사례다 — 나는 **평균만 맞추고
크기는 안 맞췄고**, 맞추지 않은 그 공변량이 신호를 날랐다.

### 최종 판독 (제대로 벌어낸 이중해리)

```
                        정체        크기
vector                1.0000      1.0000
s:norm                0.5024      1.0000   ← 크기는 완벽, 정체는 우연
s:mean (프로덕션)     0.5014      0.5383   ← 둘 다 우연
```

⟹ **레인 정체는 오직 위치 패턴에만 산다.** 벡터는 그걸 읽고, 어떤 스칼라 요약도 못 읽는다.
그리고 프로덕션이 쓰는 `mean` 은 **크기조차** 못 읽는다(로짓공간에서 평균은 softmax-무효
방향이므로).
