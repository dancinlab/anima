```

ctx  = Σ_i a_ti (V m_i)                            지금 무엇에 주의하고 있나
g_t  = (U h_t) ⊙ ctx                               ★ 곱셈 — 멀리 떨어진 두 내용이 만난다
out  = logits + λ·W_o[g_t ; h_t]
```

## CONFLICTS — 진짜 충돌 3건

**① 수용야 밖은 도출된 0 인가** — Fable *예* / Sol *아니오, 이미 binder 가 있다*
**⟹ Sol 이 옳다.** 위 코드 판정. `mbnd=False` 는 기본값이지 구조가 아니다.

**② 이름 반복 DV 를 무엇이라 부를 것인가** — Fable *ctx-identity 전송을 먼저* /
Sol *단일 이름 반복 DV 는 결합 아니라 **복사**라 거부*
**⟹ 둘 다 부분적으로 옳다.** Fable 은 *무엇을 지을지*(전송이 빠진 원시연산), Sol 은
*무엇이라 부를지*(복사를 결합이라 하지 마라)를 말하고 있다. 해소 = **전송이라 부르고,
후보 이름을 여러 개 두어 "가장 최근/유일한 이름을 복사" 가 통과 못 하게 한다**
(Sol 의 copy-only census: 최근접·최빈·정확문자열·mentioned-bag 기저선).
⚠️ 이 해소는 토이 DV 설계를 바꾼다 — 단일-이름 토이는 지으면 안 된다.

**③ 패널 크기** — Fable *부지는 싸다, 진짜 취약점은 seed* / Sol *212 는 10점 효과에
검정력 없음(≈13점까지만) · 독립 문서 400~600 필요*
**⟹ Sol 이 더 엄격하고 그쪽을 취한다.** 둘은 배타적이지 않다(부지 싸다 ∧ 212 부족).
seed 최소 2 는 Fable, 항목 검정력은 Sol.

## NOVEL — 한쪽만 낸 것

**Fable 고유 — arity 재절단 (이 발산에서 설계를 가장 크게 바꾼 것)**
H_9875 의 1-slot/2-slot 비대칭이 **곧 이 분리의 실측**이다. 따라서 G1-ctx 는 이진이 아니라 사다리:

```
ctx-identity  (arity 1 · 조밀 · 지름길 막힘 · 지금 지을 수 있음)
      ↓
ctx-relation  (arity 2 · H_9875 arity 벽 뒤에 앉아 있음)
      ↓
G1-weight     (공급 고갈 ∧ arity 벽 둘 다)
```
⟹ **arity-2 ctx 를 먼저 겨냥하면 H_9875 를 더 비싸게 재측정하고 새 벽이라 부르게 된다.**

**Fable 고유 — "기울기는 구조를 만들지 못한다"**: 트랜스포머에서 복사 압력이 attention 을
징발하는 건 attention 이 **징발당하려고 이미 존재**하기 때문. 여기선 함수 계급이 수용야 밖
전송을 배제하므로 조밀한 기울기가 암기 바닥으로 흩어진다. (충돌 ① 때문에 이 진술은
**기본 설정에 한해** 참이다.)

**Fable 고유 — 무료 참값-0 받침대**: 레인 없는 모델에서는 full 팔과 35B-절단 팔이
**구조적으로 동일**하다 ⟹ 0 이 아닌 Δ 는 전부 계기 결함. 레인 비교 전에 이 인증을 먼저.

**Sol 고유 — 지름길 필터의 정식화**: `H(Y|X_35)>0` 인 질량. → V6_16 이 실행했고 308배 붕괴.
**Sol 고유 — 실현 분할서 유도한 정확 영가설**: `p₀=(1/N)Σ Gᵢ/Kᵢ`, 문서로 군집한 Poisson-binomial.
**Sol 고유 — 전체 코퍼스 held-out CE 를 동결 비열등 구간 안에 둘 것**(레인이 본체를 갉지 않았다는 증명).
**Sol 고유 — pairodd 의 문자 그대로의 `g↔b` 치환은 과제 FORM 이므로 자연 256-byte 예측에 못 쓴다.**
